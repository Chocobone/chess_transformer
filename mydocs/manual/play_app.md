# 대국 앱 사용 가이드

학습한 모델과 브라우저에서 직접 두어 보는 로컬 웹 앱이다 (Task #7). 한 사람이 자기 컴퓨터에서 쓰는 확인용 도구다. 모든 명령은 저장소 루트에서 실행한다.

```
환경 설치 → 모델 파일 확인 → 서버 실행 → 브라우저 접속 → 대국
```

## 1. 환경 설치

학습 환경과 같다 ([`training_guide.md`](training_guide.md) 1절). 앱에 필요한 `fastapi`, `uvicorn`은 `requirements.txt`에 들어 있다.

```bash
pip install -r requirements.txt
pytest          # 전부 통과해야 한다 (Task #7 기준 142건)
```

GPU가 없어도 돈다 (CPU에서는 모델 수가 느리다. 4절).

## 2. 필요한 파일

서버는 시작할 때 아래 파일을 찾아, **있는 것만** 모델 목록에 올린다.

| 모델 | 파일 |
|---|---|
| 베이스 9M · 136M · 270M | `base_model/{9M,136M,270M}.pt` |
| 탈 · 카르포프 · 스미슬로프 (136M) | `base_model/136M.pt` + `runs/{tal,karpov,smyslov}_136M/adapter.pt` |

- 베이스 가중치 준비는 학습 가이드 2절을 따른다. 어댑터는 학습 결과물이다.
- 하나도 없으면 `모델 파일이 없다: base_model/*.pt, runs/*_136M/adapter.pt`를 내고 끝난다.
- 다른 위치에 있으면 `--base-dir`, `--runs-dir`로 지정한다.

## 3. 실행

```bash
python -m src.play.server                    # 같은 컴퓨터에서 접속할 때
python -m src.play.server --host 0.0.0.0     # 개발 컨테이너·WSL2 안에서 띄우고 Windows 브라우저로 접속할 때
```

시작하면 다음과 같이 출력한다. 브라우저에서 `http://localhost:4321`을 연다.

```
모델 6개: base-9M, base-136M, base-270M, tal-136M, karpov-136M, smyslov-136M
장치 cuda, 샘플링 시드 1234567
http://localhost:4321
```

| 옵션 | 기본값 | 내용 |
|---|---|---|
| `--host` | `127.0.0.1` | 듣는 주소. 다른 곳에서 접속하려면 `0.0.0.0` |
| `--port` | `4321` | |
| `--device` | CUDA가 있으면 `cuda` | `cpu`로 강제할 수 있다 |
| `--seed` | 무작위 (시작할 때 출력) | 모델 수 샘플링과 무작위 색 시드. 같은 시드와 같은 수순이면 같은 대국이 나온다 |
| `--base-dir` | `base_model` | |
| `--runs-dir` | `runs` | |

끄려면 Ctrl+C를 누른다. 진행 중인 대국은 메모리에만 있으므로 서버를 끄면 사라진다 (그 전에 PGN으로 저장한다).

### 개발 컨테이너(`chess-dev`)에서 띄울 때

`docker/compose.yml`이 컨테이너의 4321 포트를 호스트의 `127.0.0.1:4321`로 공개한다 (호스트 밖에서는 접속할 수 없다). 이 설정은 Task #7에서 추가했다. 그 전에 만든 컨테이너라면 호스트에서 한 번 다시 만든다.

```bash
docker compose -f docker/compose.yml up -d     # 호스트에서. 컨테이너를 다시 만든다 (홈 볼륨은 유지)
docker exec -it chess-dev bash
python -m src.play.server --host 0.0.0.0       # 컨테이너 안에서
```

컨테이너 안에서 `--host 0.0.0.0` 없이 띄우면 컨테이너 밖에서 접속할 수 없다.

### WSL2에서 직접 띄울 때

보통은 `--host 0.0.0.0`으로 띄우면 Windows 브라우저의 `http://localhost:4321`로 접속된다. localhost가 안 되면 WSL 안에서 `hostname -I`로 IP를 확인해 `http://<그 IP>:4321`로 연다.

## 4. 응답 시간과 GPU 메모리

RTX 4070 Ti 12 GB, float32 기준 실측이다 (자세한 값: [`task_m100_7_test.md`](../test_result/task_m100_7_test.md)).

| 상황 | 시간 |
|---|---|
| 모델 수 (9M / 136M / 270M) | 중앙값 약 9 / 40~57 / 91 ms |
| 크기를 바꾼 뒤 첫 수 (베이스 불러오기 포함) | 136M 2~6 s, 270M 약 9 s |
| 136M끼리 바꾸기 (베이스 ↔ 기사 어댑터) | 따로 기다리지 않는다 (어댑터 가중치만 바꾼다) |
| 비교 패널 (모델 4개) | 중앙값 약 180 ms |

- GPU에는 베이스 **한 크기만** 올린다. 다른 크기를 고르면 이전 크기를 내리고 새 크기를 올린다.
- 크기별 GPU 사용량은 `nvidia-smi` 기준으로 9M 약 0.4 GiB, 136M 1.5~2.3 GiB, 270M 2.5~3.2 GiB다. CUDA 문맥은 포함하고 다른 프로그램 사용분은 뺐다. 합법수가 많은 국면을 지나면 PyTorch가 잡아 두는 캐시가 늘어 범위의 위쪽이 된다.
- 270M을 쓰는 중에 비교 패널을 켜면 136M을 다시 올려야 하므로 첫 계산이 약 2 s 걸린다.

## 5. 화면 사용법

| 위치 | 내용 |
|---|---|
| 상단 바 | 비교 패널 ON/OFF, 새 대국 |
| 왼쪽 | 대국 정보 (모델, 내 색, 결과), 비교 패널 (켰을 때) |
| 가운데 | 체스판, 그 아래 모델이 고려한 후보 수 |
| 오른쪽 | 모델 이름·예상 승률, 기보, 이동 버튼(⏮ ◀ ▶ ⏭), 무르기·기권·PGN, 사용자 |

1. **새 대국**: 모델을 고르고 백·무작위·흑 가운데 하나를 누른다. 앞서 고른 모델은 다음에도 선택돼 있다. 내가 흑이면 판이 뒤집히고 모델이 먼저 둔다.
2. **수 두기**: 기물을 누른 뒤 칸을 누르거나, 끌어다 놓는다. 둘 수 있는 칸에는 점이, 잡을 수 있는 칸에는 테두리 원이 표시된다. 폰이 끝 줄에 닿으면 승진 기물 선택 창이 뜬다.
3. **모델 수**: 모델이 생각하는 동안 모델 이름 옆에 "생각 중"이 뜬다.
4. **기보**: 모델이 둔 수에는 확률 π가 붙는다 (예: `c5 72%`). π가 10% 미만인 수는 주황색으로 표시한다. 3회 반복을 만든 수에도 표시가 붙는다.
5. **되돌려 보기**: 기보의 수를 누르거나 ◀ ▶ (키보드 ←/→)로 지난 국면을 본다. 이때는 수를 둘 수 없다. ⏮(Home)은 시작 국면, ⏭(End)는 현재 국면이다.
6. **무르기**: 내가 마지막으로 둔 수까지 되돌린다 (모델 응수까지 함께 되돌린다). 기권도 무를 수 있다.
7. **기권**, **PGN**: PGN 파일(`game_날짜_모델.pgn`)을 내려받는다. 대국자 이름과 결과가 헤더에 들어 있다.
8. **새로고침**: 진행 중인 대국이 그대로 이어진다 (서버가 들고 있다).

### 후보 수 패널

모델이 마지막으로 둔 수를 고를 때의 상위 5수를 보인다. 막대와 왼쪽 숫자가 π(그 수를 고를 확률), 오른쪽 숫자가 q(그 수를 둔 뒤 모델 쪽 예상 승률)다. 실제로 둔 수는 강조한다.

### 비교 패널

상단 바의 토글로 켠다. 켜 두면 새로고침 뒤에도 유지된다 (브라우저 저장소). 보고 있는 국면에서 **베이스 136M · 탈 · 카르포프 · 스미슬로프**가 각각 어떤 수를 고를지 상위 3수와 예상 승률을 나란히 보인다. 같은 국면에서 기풍마다 무엇이 다른지 보는 용도다. 되돌려 보기 중이면 그 국면을 계산하고, 그 국면에서 실제로 둔 수를 강조한다. 끄면 계산하지 않는다.

## 6. 모델이 수를 고르는 방식

- 모델은 국면의 모든 합법수에 대해 q(s, a)(그 수를 둔 뒤의 예상 승률)를 계산한다. 이를 학습과 같은 온도로 확률로 바꾼다: π(a|s) = softmax(q / T), **T = 0.02**.
- 수는 π에서 **샘플링**한다. 학습한 정책 그대로이므로 대부분 1위 수를 두지만, 확률이 비슷한 수가 여럿이면 다른 수를 두기도 한다. 그래서 같은 국면에서도 수가 달라질 수 있다 (재현하려면 `--seed`).
- 앱의 π는 학습·평가 코드와 같은 함수로 계산한다. 보고서에 나온 평가값과 같은 정의다.
- 탐색은 하지 않는다. 한 번의 순전파로 고른다.

## 7. 알려진 한계

- **모델은 FEN만 본다.** 지난 수순을 모르므로 같은 국면이 반복되는지 알 수 없다. 이기는 국면에서도 3회 반복으로 무승부가 날 수 있다. 앱은 같은 국면이 **실제로** 세 번 나오면 무승부로 끝낸다 (lichess와 같음). 50수 규칙도 자동으로 적용한다.
- 지금 어댑터는 α = 0(모방 항과 기력 항만)으로 학습한 것이다. 기풍 차이는 크지 않을 수 있다 (README 결과 요약).
- 기사 어댑터는 136M에만 있다. 9M·270M은 베이스뿐이다.
- 대국은 하나만, 메모리에만 둔다. 서버를 끄면 사라진다. 여러 사람이 동시에 쓰는 것은 고려하지 않았다.
- 시간 제한(대국 시계)은 없다.

## 8. 자주 나는 오류

| 증상 | 원인과 해결 |
|---|---|
| `모델 파일이 없다: ...`로 끝남 | 2절의 파일이 없다. 경로가 다르면 `--base-dir`, `--runs-dir` |
| 브라우저에서 접속이 안 됨 (컨테이너) | `--host 0.0.0.0` 없이 띄웠거나, 컨테이너가 포트 공개 전에 만들어졌다. 3절대로 다시 만든다 |
| 브라우저에서 접속이 안 됨 (WSL2) | `--host 0.0.0.0`으로 띄우고, localhost가 안 되면 WSL IP로 연다 |
| `[Errno 98] address already in use` | 이미 서버가 떠 있다. 끄거나 `--port`를 바꾼다 |
| "서버에 연결하지 못했습니다" 알림 | 서버가 꺼졌다. 다시 띄우고 새로고침한다 (진행 중이던 대국은 사라졌다) |
| 크기를 바꾼 뒤 첫 수가 몇 초 걸림 | 정상이다. 베이스를 불러오는 시간이다 (4절) |
| CUDA out of memory | 다른 프로그램(학습 등)이 GPU를 쓰고 있다. 그 작업을 끝내거나 `--device cpu` |
