# Task #1: 기사별 기보(PGN) 전처리 및 LoRA 파인튜닝 학습 코드 작성 — 수행 계획서

## 수행 목표

`model_tal/`, `model_karpov/`, `model_smyslov/`의 기보(PGN)를 국면 단위 학습 데이터로 전처리하고,
동결된 공유 베이스(DeepMind searchless_chess action-value Transformer) 위에 기사별 LoRA 어댑터를
학습할 수 있는 PyTorch 코드를 작성한다. 이 타스크의 산출물은 "GPU 서버에서 바로 실행 가능한
전처리·학습 코드"이며, 실제 학습 결과의 분석과 스타일 평가는 후속 타스크로 둔다.

## 범위

1. **PGN 전처리**: 기사별 PGN → 국면 단위 데이터셋(FEN, 기사가 둔 수, 메타데이터), train/val 분할
2. **베이스 모델 PyTorch 이식**: searchless_chess Transformer(136M/270M)를 PyTorch로 재구현하고 공개 체크포인트 가중치를 로드
3. **LoRA 어댑터**: 베이스 동결 + 어텐션 선형층에 LoRA 주입, 어댑터만 저장/로드
4. **학습 스크립트**: 기사 이름과 설정만 바꿔 세 기사에 대칭 적용 가능한 학습 루프

### 범위 외 (후속 타스크)

- 스타일 특성 벡터 f(s,a) 라벨링(Stockfish 2회 탐색), 방향 벡터 w_p 추정 (제안서 4.1~4.2)
- α 스윕, 평가(지표 이동·지문 거리·혼동 행렬·대국 성적·블라인드 테스트) (제안서 6장)
- 웹 서비스 배포

## 핵심 설계 원칙

- **세 기사에 완전 대칭**: 전처리·모델·학습 코드는 하나이며, 기사 차이는 입력 PGN과 설정 값뿐이다 (제안서 5.3 "동일 설정 대칭 적용").
- **베이스 동결**: 베이스 가중치는 학습하지 않고 LoRA 파라미터만 학습한다.
- **국면 단위 학습**: 판이 아니라 "대상 기사가 둘 차례인 국면"이 학습 단위다. 상대의 수는 학습 대상이 아니다.
- **이식 정확성 우선**: PyTorch 이식 모델이 원본과 같은 출력을 내는지 검증한 뒤에 LoRA를 얹는다. 이식이 틀리면 이후 모든 결과가 무의미하다.
- **손실함수는 제안서 4.3의 구조를 따르되 단계적으로 구현**: 이번 타스크는 모방 항과 기력 항까지 구현하고, 스타일 항은 α=0 기본값의 인터페이스만 열어 둔다 (특성 라벨이 아직 없으므로).

## 기존 구현 현황

소스 코드는 신규 구현이다. 현재 저장소에 있는 것:

- `model_tal/Tal.pgn`: 2,431판 (1952~1992)
- `model_karpov/Karpov.pgn`: 3,529판 (1961~2022)
- `model_smyslov/Smyslov.pgn`: 2,627판 (1939~2001)
- `base_model/download.sh`: 136M, 270M 체크포인트 다운로드 스크립트
- `paper/`, `docs/`: 원 논문, 캡스톤 제안서

### 사전 조사 결과

**기보 데이터**

| 항목 | 탈 | 카르포프 | 스미슬로프 |
|------|-----|---------|-----------|
| 판 수 | 2,431 | 3,529 | 2,627 |
| 결과 `*`(미완) | 1 | 11 | 0 |
| 이벤트명에 simul/blitz/rapid/blind/exhib 포함 | 71 | 890 | 48 |
| 기사 이름 표기 | `Tal, Mihail` 1종 | `Karpov, Anatoly` / `Karpov,Ana` / `Karpov,An` 3종 | `Smyslov, Vassily` 1종 |

- 세 파일 모두 주석·변화수·NAG가 없는 깨끗한 본선 기보이며 태그 구성도 동일하다 (Elo 태그는 대부분 공란).
- 카르포프만 이름 표기가 3종이라 정규화가 필요하다. 접두어 `Karpov`로 매칭하되 `Kasparov` 등 다른 기사와 섞이지 않게 한다.
- 카르포프는 속기·다면기 계열 판이 약 25%로 다른 두 기사(약 2~3%)보다 훨씬 많다. 기본 제외로 확정했다 (아래 확정 사항 2). 위 표의 키워드 외에 `sim`, `TV`, `Internet` 등으로 표기된 판이 카르포프에 추가로 있어, 제외 후 카르포프는 약 2,500판 내외가 될 것으로 보인다.
- 기사가 둔 수만 추출하면 기사당 대략 10만 국면 내외로 예상된다 (정확한 수는 Stage 1 보고서에 기재).

**베이스 모델 (google-deepmind/searchless_chess)**

- 원본은 **JAX/Haiku** 구현이고 체크포인트도 Haiku 파라미터 형식이다. 본 프로젝트 기술 스택은 PyTorch이므로 이식이 필요하다.
- 구조: decoder-only Transformer, 인과 마스크 없음, 학습형 위치 인코딩, pre-LN + 최종 LN, 어텐션 q/k/v에 bias 없음, MLP는 SwiGLU, widening factor 4.
- 136M: 8층 / 270M: 16층, 둘 다 임베딩 1024, 헤드 8.
- 입력: FEN을 77토큰으로 고정 길이 토큰화 + 행동 토큰 1개 + 더미 리턴 토큰 1개 = 79토큰. 행동 공간은 1,968개.
- 출력: 마지막 위치에서 128개 승률 구간에 대한 로그확률. 구간 중심값과 내적하면 그 수의 예상 승률 q(s,a)가 된다.
- **action-value 모델이므로 정책 헤드가 없다.** 한 국면의 정책을 얻으려면 합법수마다 순전파를 1회씩 해야 한다 (국면당 평균 30회 내외). 학습 비용과 손실 설계에 직접 영향을 준다.

## 손실함수 설계 방향

정책은 합법수들의 예상 승률에 온도 softmax를 적용해 정의한다: π(a|s) = softmax_a( q(s,a) / T ).

| 항 | 이번 타스크 | 내용 |
|----|------------|------|
| 모방 항 | 구현 | 기사가 실제로 둔 수에 대한 교차엔트로피. 제안서의 "베이스 대비 잔차" 형태는 동결 베이스 정책을 사전분포로 두는 옵션으로 제공 |
| 기력 항 | 구현 | 동결 베이스의 q로 계산한 regret이 τ를 넘는 수에 대한 힌지 벌점. 외부 엔진 불필요 |
| 스타일 항 | 인터페이스만 | 특성 텐서와 w_p를 받는 자리만 두고 기본 α=0. 특성 라벨링 타스크 이후 활성화 |

동결 베이스의 q(s,a)는 학습 중 변하지 않으므로 전처리 시 한 번만 계산해 캐시하면 학습 시 순전파가 절반으로 준다. 이 캐시 단계의 포함 여부는 구현 계획서에서 확정한다.

## 확정 사항 (2026-10-07 작업지시자 결정)

1. **베이스 모델 프레임워크**: PyTorch로 이식한다. 순서는 (1) PyTorch로 구조 재작성 → (2) Haiku 체크포인트를 `state_dict`로 변환 → (3) GPU 서버에서 원본 JAX 코드로 기준 출력을 1회 추출 → (4) PyTorch 출력과 수치 비교. JAX는 (3)에서만 쓰고 학습 코드에는 의존성을 남기지 않는다.
2. **속기·다면기 판 처리**: **기본 제외**한다. 세 기사의 데이터 규모를 비슷하게 유지하기 위함이다. 제외 대상은 이벤트명 기준 속기(blitz/rapid), 다면기(simul/sim), 블라인드, 시범·TV·인터넷 대국이며, 정확한 규칙과 제외 후 판 수는 Stage 1에서 확정·보고한다. 포함 옵션은 남겨 둔다.
3. **베이스 크기**: 개발·검증은 136M, 본 학습은 270M. 코드는 둘 다 지원한다.
4. **문서 표기**: 마일스톤은 `m100`. 오늘 할일 파일명은 `yyyymmdd.md`로 통일한다 (CLAUDE.md 파일명 규칙 표 수정 완료).
