# Task #12: 특성 없는 평가 (A1~A3, B2·B3·B10, C3) — 수행 계획서

> **상태 (2026-11-12)**: 승인. 결정 요청 4건 모두 권장안 (작업지시자 결정)

## 수행 목표

평가 기준 문서 `mydocs/tech/evaluation_criteria.md`의 지표 가운데 특성(f(s,a), w_p)과 대국이 필요 없는 것을 평가 코드로 구현한다. 그 코드로 α = 0 어댑터를 평가해 기준선과 판정을 낸다. 기준 문서 8.3절 후속 이슈 순서 3번이다.

끝 상태는 다음과 같다.

- 특성 없는 A(A1~A3), 특성 없는 층 B(B3 전제 + B10), C3의 판정을 기사별 표와 함께 낸다
- 같은 코드로 α > 0 어댑터(후속 이슈 6·7)를 다시 평가할 수 있다

## 범위

1. **모델 출력 덤프 (GPU 서버)**
   - 모델 하나를 S_val 전체(세 기사 val 합집합, 368국 13,846국면)에서 평가한다. 국면마다 합법수 전체의 log π를 파일로 남긴다
   - 정책 정의는 학습·평가와 같다: temperature 0.02, float32(`eval_amp` false), 합법수만
   - 대상은 어댑터 6개다: R1·R2·R8, R1s0·R2s0·R8s0 (`runs/gpu/`)
   - 베이스는 학습 기준선과 같이 캐시의 베이스 q(`base_q_136M.npz`)로 계산한다. GPU가 필요 없다
   - 모델과 관계없는 국면 정보도 한 번 남긴다: 기사, `game_id`, ply, 기사가 둔 수, 베이스 기준 regret, "새 국면" 여부(2.4절, ply 20 이상이고 FEN 앞 4필드가 세 기사 어느 train에도 없음)
2. **지표와 판정 (CPU)**: 덤프만 읽어 계산한다. 대국 단위 부트스트랩(10,000회, seed 0, 백분위 95%, 2.2절)을 쓴다

   | # | 지표 | 판정 대상 | 기준 문서 |
   |---|---|---|---|
   | A1 | Δtop1, Δimitation (어댑터 − 베이스, 자기 기사 val). top3·ply 20 이상은 보고 | R1·R2·R8 | 3.3절 |
   | A2 | 새 국면 Δtop1. 국면 수·대국 수 보고 | R1·R2·R8 | 3.3절 |
   | A3 | 불일치 국면 순 적중률 r. \|D\| 비율, ply 분포, McNemar p(참고) 보고 | R1·R2·R8 | 3.3절 |
   | B2 | 정책 거리 d(JS, 밑 2)와 1순위 불일치율 δ. 6개 모델의 모든 쌍 | 보고 | 4.3절 |
   | B3 | 잡음 바닥 n_p = d(Rs0, R), 여유 M(p, q) = d(p, q) − max(n_p, n_q) | 전제 | 4.3절 |
   | B10 | 우도 혼동 행렬(ply 20 이상, k = 1), 3지선다 재현율과 쌍별 2지선다. 열 합계, 전체 구간, k = 2·5·10 보고 | R1·R2·R8 | 4.3절 |
   | C3 | regret_top1 평균(자기 기사 val). regret, band_violation, strength 보고 | R1·R2·R8 (단독 판정 불가) | 5.4절 |

   - 판정 규칙은 2.5절, 3.5절, 4.7절을 그대로 따른다. 조건 값은 바꾸지 않는다
   - seed 0 대조군(R1s0·R2s0·R8s0)은 B3의 입력으로만 쓴다. A·B10·C3 값은 참고로 함께 보고한다
3. **검증**
   - 덤프로 다시 계산한 top1·imitation·regret_top1이 각 학습 `log.jsonl`의 마지막 eval·baseline과 같은지 본다(자기 기사 val)
   - 지표 함수는 손으로 계산할 수 있는 작은 예제로 단위 테스트한다
4. **결과 정리**
   - `mydocs/test_result/task_m100_12_test.md`: 덤프 실행 기록, 지표 값과 구간, 판정 표
   - 판정 결과는 최종 보고서에 정리한다. 기준 문서 3.6·4.8·5.8절(α = 0 기준선)의 갱신은 결정 요청 4

## 핵심 설계 원칙

- **GPU 계산과 통계를 나눈다.** GPU에서는 모델 출력만 남기고, 지표·부트스트랩·판정은 그 덤프로 CPU에서 계산한다. 지표를 고치거나 추가해도 GPU를 다시 쓰지 않는다. α > 0 어댑터도 덤프만 더하면 된다
- **정의는 기준 문서를 그대로 옮긴다.** 함수마다 기준 문서의 절과 식을 docstring에 적는다. 정의가 모호한 곳은 구현 계획서에 해석을 적고 승인받는다
- **학습 지표와 대조한다.** 덤프로 다시 계산한 지표가 학습 기록과 같아야 덤프를 믿는다
- **판정은 기계적으로 낸다.** 구간과 조건으로 통과·실패·보류를 코드가 내고, 사람이 결과를 보고 기준을 바꾸지 않는다
- **같은 장비에서 덤프한다.** B2·B3는 모델 사이의 작은 정책 차이를 잰다. 6개 모델을 같은 GPU 기종에서 덤프해 장비 차이가 거리에 섞이지 않게 한다 (결정 요청 2)

## 기존 구현 현황

- `src/train/train.py`의 `evaluate`: 같은 정책 정의로 val 지표를 국면 평균으로 낸다. 국면별 값은 남기지 않는다
- `src/train/policy.py`(`policy_from_q`, `pad_by_owner`), `src/data/dataset.py`(`PositionDataset`, `split_by_moves`): 그대로 쓴다
- `src/model/lora.py`의 `load_adapter`, `src/model/transformer.py`의 `load_base`: 그대로 쓴다
- `gpu_train/eval_adapter.py`, `eval.sbatch`, `submit_eval.sh` (Task #11): 학습 폴더 하나를 sbatch로 평가하는 틀. 덤프 작업도 같은 틀을 따른다
- `gpu_train/site.env`의 `SBATCH_EXTRA`: `--nodelist` 등으로 계산 노드를 고를 수 있다
- 데이터(`data/processed/`)와 베이스 q 캐시는 이 작업 사본에 없다. 서버에는 `fetch_inputs.sh`로 받아 둔 입력이 있다
- 대국 단위 부트스트랩: Task #6에서 스크래치패드 스크립트로만 했다. 저장소에 코드가 없어 새로 만든다
