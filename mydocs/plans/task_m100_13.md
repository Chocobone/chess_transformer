# Task #13: 대국 실행기 (Stockfish, 오프닝 세트, C1·C2·C4) — 수행 계획서

> **상태 (2026-11-16)**: 승인. 결정 요청 6건 모두 권장안 (작업지시자 결정)

## 수행 목표

평가 기준 문서 `mydocs/tech/evaluation_criteria.md` 5절(주장 C 기력)의 판정에 필요한 대국 실행기와 Stockfish 기준 수 품질 도구를 만든다. 기준 문서 8.3절 후속 이슈 순서 5번이다. 기준 문서가 이 이슈에서 정하라고 남긴 값 네 가지를 α > 0 결과 전에 고정하고, 2.7절 절차에 따라 정정으로 기록한다.

| 고정할 값 | 기준 문서 |
|---|---|
| 오프닝 세트 출처(라이선스 포함)와 국면 200개 | 5.3절 |
| Stockfish 버전 | 5.4절 C2 |
| C2 노드 수 (베이스 점수율 0.35~0.65가 되는 값) | 5.4절 C2 |
| C4 탐색 깊이와 센티폰→승률 변환식 | 5.4절 C4 |

끝 상태는 다음과 같다.

- 위 네 값이 기준 문서에 정정으로 기록되어 있다
- 모델 ID 하나를 주면 C1(베이스 상대)·C2(Stockfish 상대) 400국과 C4 수 품질을 GPU 서버에서 낼 수 있다
- 기보와 덤프만으로 C1·C2·C4 값·구간·판정을 CPU에서 낼 수 있다
- (결정 요청 5) α = 0 어댑터 R1·R2·R8의 C1·C2·C4 기준선이 있다

## 범위

1. **오프닝 세트**
   - 공개 엔진 테스트용 오프닝 세트에서 양쪽 4수(8 ply) 국면을 고른다. 출처와 라이선스를 확인해 기록한다 (결정 요청 2)
   - 고정한 Stockfish로 평가해 ±50 센티폰 안인 국면만 남기고, 고정 seed로 200개를 뽑는다
   - 결과 파일(번호, FEN, 수순, 평가값)을 저장소에 커밋한다. 모든 조합이 같은 200개를 쓴다
2. **대국 실행기**
   - 기준 문서 5.3절 조건을 그대로 따른다: π 샘플링(temperature 0.02), 대국마다 seed 기록, 오프닝마다 색을 바꾼 2국(짝), 400 ply 초과는 무승부, 평가값 판정 없음
   - 종료: 체크메이트, 스테일메이트, 실제 3회 반복, 50수 규칙, 기물 부족 (Task #7 대국 앱 `src/play/game.py`와 같은 처리)
   - 상대: 모델 대 모델(C1), 모델 대 Stockfish(C2, 노드 수 고정, `Threads = 1`, `Hash` 고정)
   - 정책 계산은 학습·대국 앱과 같은 함수(`legal_action_tokens`, `policy_from_q`)를 쓴다
   - 모든 대국을 PGN으로 저장한다 (헤더: 오프닝 번호, 색, seed, 모델 ID, Stockfish 버전·노드 수, 종료 사유)
   - 중단 뒤 이어서 돌릴 수 있게 대국 단위로 저장하고, 끝난 대국은 건너뛴다
3. **C2 노드 수 보정**
   - 베이스 136M을 노드 수 후보 3개와 100국(50짝)씩 둔다. 점수율이 0.35~0.65인 노드 수를 고른다 (5.4절)
   - 후보가 모두 범위 밖이면 범위를 좁혀 다시 보정한다. 보정 대국은 판정에 쓰지 않는다
4. **C4 수 품질 도구**
   - S_val 13,846국면에서 Stockfish 최선수와 모델 1순위 수를 고정 깊이로 평가한다. 손실 ℓ = W(최선수) − W(모델 수)
   - (국면, 수) 단위로 캐시해 모델이 늘어도 새 수만 평가한다
   - 모델 1순위 수는 Task #12 덤프(`runs/gpu/dump/`)에서 읽는다. GPU를 다시 쓰지 않는다
5. **집계와 판정 (CPU)**
   - C1·C2: 짝 단위 부트스트랩(10,000회, seed 0)으로 점수율과 Elo, 95% 백분위 구간. C2는 같은 오프닝 짝끼리 쌍대로 (어댑터 − 베이스) 차이
   - C4: 1순위 수 평균 손실 차이(어댑터 − 베이스), 대국 단위 쌍대 부트스트랩. 큰 실수(ℓ ≥ 0.20) 비율은 보고
   - 판정 조건 값은 기준 문서 5.4절 그대로다 (−50 Elo, 손실 0.02)
   - C7(승리 전환율, 3회 반복 비율)의 반복 비율은 기보로 계산해 보고한다. 승리 전환율은 대국 중 Stockfish 평가가 필요해 이 타스크에서는 하지 않는다
6. **서버 실행 틀** (`gpu_train/`): Stockfish 설치 확인, 대국·C4 작업 sbatch, 회수
7. **결과 정리**: `mydocs/test_result/task_m100_13_test.md`, 기준 문서 정정

## 핵심 설계 원칙

- **대국 앱과 같은 정책을 쓴다.** 수 선택은 학습·평가·대국 앱과 같은 함수와 같은 온도로 한다. 대국 앱 코드는 고치지 않고, 새 코드가 같은 하위 함수를 부른다
- **값은 결과를 보기 전에 고정한다.** 오프닝, Stockfish 버전, 노드 수, 깊이, 변환식은 α > 0 대국 전에 정정으로 기록한다. 노드 수 보정은 베이스만으로 한다
- **재현할 수 있게 기록한다.** 대국마다 seed, Stockfish 버전·옵션, 모델 SHA-256을 남긴다. 같은 seed·같은 장비면 같은 기보가 나와야 한다
- **대국 실행과 집계를 나눈다.** 서버는 기보(PGN)와 C4 캐시만 남기고, 부트스트랩·판정은 Task #12처럼 CPU에서 한다
- **기존 평가 코드를 다시 쓴다.** 부트스트랩·판정은 `src/eval/stats.py`, 모델 1순위 수는 Task #12 덤프를 쓴다

## 기존 구현 현황

- `src/play/engine.py`의 `Engine`: 모델 ID와 FEN으로 π를 계산하고 샘플링한다. 136M에는 LoRA를 한 번 주입하고 어댑터마다 가중치만 바꿔 끼운다. 한 국면씩 계산한다. 어댑터 위치는 `runs/{player}_136M/`으로 정해져 있어, `runs/gpu/R*`를 쓰려면 `ModelSpec`을 직접 만들어 넘긴다
- `src/play/game.py`: 종료 처리(실제 3회 반복, 50수 규칙 등)와 기보 기록. 대국 실행기의 종료 규칙 기준이다
- `src/train/policy.py`(`legal_action_tokens`, `policy_from_q`), `src/model/lora.py`, `src/model/transformer.py`: 그대로 쓴다
- `src/eval/stats.py`(부트스트랩, 백분위 구간, 판정), `src/eval/dump.py`(S_val 덤프, `positions.npz`): Task #12. 그대로 쓴다
- `gpu_train/dump.sbatch`, `submit_dump.sh`: 서버 작업 틀. 대국·C4 작업도 같은 틀을 따른다
- `python-chess`(`chess>=1.11`)가 이미 의존성에 있다. UCI 엔진 연결(`chess.engine`)을 쓸 수 있다
- Stockfish는 로컬·서버 어디에도 아직 설치되어 있지 않다
- 136M 응답 시간: 대국 앱 경유 수당 중앙값 41.5~56.9 ms (Task #7, 로컬 RTX 4070 Ti)

## 위험과 대응

| 위험 | 대응 |
|---|---|
| 대국 시간이 추정(8,700국 10~13시간)보다 길다. 서버 A2000은 로컬보다 느리다 (학습 2.5~2.8배) | 1단계에서 서버 실측으로 다시 추정한다. 여러 대국을 동시에 진행하고 같은 모델 차례의 국면을 묶어 한 번에 계산한다(배치). 배치가 결과를 바꾸지 않는지(같은 seed면 같은 기보) 테스트한다 |
| C4 탐색이 길다 (4만~6만 회, depth 18) | 서버 CPU에서 여러 Stockfish 프로세스를 병렬로 돌린다. 1단계에서 회당 시간을 재어 깊이 제안(18)이 감당되는지 본다. 감당이 안 되면 깊이를 결과 전에 정정으로 정한다 |
| 노드 수 후보가 모두 0.35~0.65 밖이다 | 후보를 넓게 잡고(결정 요청 4), 범위 밖이면 이분 탐색으로 한 번 더 보정한다. 보정 결과를 그대로 기록한다 |
| Stockfish가 장비·스레드에 따라 다른 결과를 낸다 | `Threads = 1`, `Hash` 고정, 노드 수·깊이 제한으로 탐색을 결정적으로 만든다. 버전과 빌드를 기록한다 |
| 오프닝 세트의 라이선스가 불분명하다 | 출처 저장소의 라이선스를 확인해 기록한다. 불분명하면 국면 파일을 커밋하지 않고 받는 스크립트만 둔다 |
| FEN만 보는 모델이 반복을 피하지 못해 무승부가 많다 | 기준 문서대로 실제 3회 반복만 무승부로 둔다. 반복 종료 비율을 C7로 보고한다 |

## 결정 요청

1. **코드 위치**
   - 권장: `src/match/`에 새 패키지를 둔다(오프닝 세트, Stockfish 연결, 대국 실행기, C4 탐색). 집계·판정은 `src/eval/`에 `games.py`(C1·C2·C4)로 더한다. 서버 실행 틀은 `gpu_train/`에 `match.sbatch`, `submit_match.sh` 등으로 둔다. 테스트는 `tests/test_match_*.py`다
   - 이유: 후속 이슈 "평가 실행과 판정"이 같은 코드를 다시 쓴다. `src/play/` 등 기존 파일은 고치지 않는다
   - 대안: `src/play/`에 넣어 대국 앱과 함께 둔다
2. **오프닝 세트 출처**
   - 권장: Stockfish 개발 테스트(Fishtest)가 쓰는 공식 오프닝 저장소 `official-stockfish/books`의 8수 세트(`8moves_v3`)에서 고른다. 양쪽 4수(8 ply)라 기준 문서 5.3절과 맞고, 엔진 테스트용 중립 오프닝이다. 라이선스는 1단계에서 확인한다
   - 대안: 다른 공개 세트(예: UHO 계열). UHO는 한쪽이 유리한 국면을 일부러 고른 세트라 ±0.5폰 조건과 맞지 않는다
3. **Stockfish 버전과 설치**
   - 권장: 1단계 시점의 최신 공식 릴리스 하나로 고정한다. 서버에는 conda-forge `stockfish` 패키지로 학습용 conda 환경에 설치하고, 로컬 개발 컨테이너에도 같은 버전을 둔다. 버전 문자열과 실행 파일 SHA-256을 기록한다
   - 대안: 공식 바이너리를 받아 `gpu_train/` 설치 스크립트로 둔다 (conda 패키지가 없거나 버전이 늦을 때)
4. **C2 노드 수 후보와 C4 승률 변환식**
   - 노드 수 권장: 후보를 1단계의 짧은 시험 대국(후보당 약 20국)으로 좁힌 뒤, 본 보정 3개 × 100국을 한다. 136M의 강도(베이스 논문 기준 대략 Lichess 블리츠 2,300 수준)를 보면 수천~수만 노드 범위로 예상한다
   - 변환식 권장: W(cp) = 1 / (1 + exp(−0.00368208 · cp)). 베이스 모델(searchless_chess)이 학습 라벨을 만들 때 쓴 Lichess 승률 변환식과 같아, C3의 q와 같은 척도다. 메이트 점수는 승률 1 또는 0으로 둔다
   - 대안 (변환식): Stockfish 내장 WDL 모델. 버전마다 계수가 바뀐다
5. **α = 0 기준선 대국을 이 타스크에서 할지**
   - 권장: 한다. R1·R2·R8의 C1(3 × 400국), 베이스와 R1·R2·R8의 C2(4 × 400국), C4를 잰다. 실행기를 실제 규모로 끝까지 검증하고, D 판정의 비교군(α = 0, 기준 문서 5.1절)을 미리 확보한다. 약 3,100국이며, 서버 실측으로 다시 추정한다
   - 대안: 보정(300국)과 C4 도구 검증까지만 하고, 모든 대국은 후속 이슈 "평가 실행과 판정"에서 한다
6. **실행 장소**
   - 권장: 대국과 C4는 GPU 서버에서 Slurm 작업으로 돌린다(기준 문서 5.6절). 집계·판정은 로컬 개발 컨테이너(CPU)에서 한다. 오프닝 선별은 탐색량이 작아 로컬에서 한다
   - 대안: 대국도 로컬 RTX 4070 Ti에서 돌린다. 빠르지만 서버 학습·덤프와 장비가 달라진다
