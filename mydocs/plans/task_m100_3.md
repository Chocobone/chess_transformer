# Task #3: 카르포프 LoRA 어댑터 본 학습 (136M) — 수행 계획서

## 수행 목표

Task #2에서 탈에 쓴 것과 같은 코드·같은 설정으로 카르포프의 LoRA 어댑터를 3 epoch(9,039 갱신) 끝까지 학습한다.
베이스는 136M, 실행 위치는 로컬 개발 컨테이너의 GPU(RTX 4070 Ti 12GB)다.
산출물은 어댑터(`runs/karpov_136M/adapter.pt`)와, 베이스 기준선 대비 val 지표 변화를 정리한 학습 결과 문서(`mydocs/test_result/task_m100_3_test.md`)다.

## 범위

1. **사전 확인**: `pytest`, 카르포프 q 캐시의 SHA-256 대조, GPU 상태, 실행 스크립트 점검
2. **카르포프 어댑터 학습**: 탈과 같은 설정, `--resume`과 자동 재시도 스크립트 사용
3. **학습 검증과 결과 정리**: 로그 연속성, 어댑터 재평가, 탈과의 설정 동일성 확인. 실행 명령·설정·베이스 기준선·val 지표 추이를 `mydocs/test_result/task_m100_3_test.md`에 기록

### 범위 외

- 스미슬로프 어댑터 학습 (별도 이슈, 2026-10-14)
- 세 기사 결과 종합, `mydocs/manual/training_guide.md` 갱신 (별도 이슈). 탈 결과와의 비교는 이 타스크에서 하지 않는다. 설정이 같은지만 확인한다

- 270M 베이스 학습, 스타일 항 학습, α 스윕, 평가(지문 거리·혼동 행렬·대국 성적)
- 어댑터가 카르포프의 스타일을 반영하는지에 대한 판단. val 모방 지표와 기력 지표까지만 본다

## 핵심 설계 원칙

- **탈과 같은 설정, 같은 코드**: `--player`와 `--out`만 다르다 (2026-10-12 작업지시자 결정). 코드는 재개 기능을 넣은 뒤의 커밋(`06b57fa` 이후) 그대로 쓴다.
- **소스는 수정하지 않는다**: `src/`, `scripts/`, `tests/`를 건드리지 않는 실행 작업이다. 실행 중 코드 결함이 드러나면 멈추고 원인과 수정안을 보고한 뒤 승인을 받아 수정한다.
- **결과는 있는 그대로 기록한다**: 좋아지지 않았거나 나빠진 지표도 수치를 그대로 적는다.
- **수치는 손으로 옮겨 적지 않는다**: 결과 문서의 표는 `log.jsonl`에서 스크립트로 뽑는다.

### 학습 명령과 설정

```bash
python -u -m src.train.train --player karpov --base base_model/136M.pt \
    --out runs/karpov_136M --eval-every 1000 --resume
```

나머지는 기본값이다 (rank 16, lora-alpha 32, targets q k v o, T 0.02, λ 1.0, τ 0.02, γ 0, α 0, lr 1e-4, 3 epoch, 국면 32개/갱신, 합법수 한도 128, `--checkpoint-every 200`, seed 0). 실제 실행은 `runs/logs/train_player.sh karpov`로 하고 `setsid nohup`으로 세션과 분리한다. 로그는 `runs/logs/train_karpov_136M.log`.
