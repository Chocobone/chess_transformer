# Task #6: 세 기사 136M 어댑터 학습 결과 종합, 실행 가이드 갱신 — 수행 계획서

## 수행 목표

탈(Task #2)·카르포프(Task #3)·스미슬로프(Task #4)의 136M LoRA 어댑터 학습 결과를 같은 기준의 표와 곡선으로 한곳에 모은다. 세 학습의 조건 차이와 한계도 함께 정리해, 다음 단계(스타일 특성·방향 벡터, α 스윕)가 기댈 기준 문서를 만든다.
세 학습에서 얻은 운영 지식으로 `mydocs/manual/training_guide.md`를 갱신한다.

## 범위

1. **수치 종합** (GPU 불필요): 세 기사의 `runs/{player}_136M/`(`config.json`, `log.jsonl`)과 실행 로그에서 스크립트로 뽑는다.
   - 데이터 규모(국·국면·합법수), 학습 설정 대조, 갱신 수
   - val 7개 지표의 기준선 → 최종 변화, 평가 시점별 곡선
   - 소요 시간, 처리량, GPU 메모리, 평가 시간, 중단·재개 이력
2. **조건 차이와 한계 정리**
   - 재개 구간의 데이터 순서가 끊기지 않은 학습과 다름 (Task #5 추정치)
   - `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`는 스미슬로프만 썼음 (결과에 영향 없음을 Task #4에서 확인한 범위)
   - val 세트가 기사마다 달라 지표의 절대값을 기사끼리 직접 비교할 수 없다는 점. 기준선 대비 변화로 비교한다
3. **교차 평가 (선택, 아래 "결정 요청" 참고)**: 각 어댑터를 세 기사의 val에 평가해 3×3 표를 만든다. 자기 기사의 수를 다른 기사 어댑터보다 더 잘 맞히는지(대각선이 가장 좋은지)를 본다. 대각선 3칸은 이미 있으므로 새 평가는 6회다 (GPU, 회당 약 3분, 합계 약 20분). 소스 수정 없이 스크래치패드 스크립트로 한다.
4. **실행 가이드 갱신** (`mydocs/manual/training_guide.md`)
   - 136M 본 학습의 실측 소요 시간(3.1~3.6시간)과 자원 사용량
   - 학습 뒤 평가가 GPU 메모리를 넘쳐 느려지는 문제와 대책 `expandable_segments:True`. 환경변수는 `config.json`에 남지 않으므로 실행 기록에 적는 방법
   - 자동 재시도 스크립트(`runs/logs/train_player.sh`)를 쓰는 중단·재개 운영. 중단 지점은 실행 로그의 실패한 시도 마지막 train 줄로 적는다
   - CUDA 오류 대응 기술을 세 학습의 이력으로 갱신
   - 7절 "결과 저장"을 실제로 해 온 방식에 맞춘다
5. **종합 문서**: `mydocs/report/task_m100_6_report.md`에 위 결과를 담는다. 이후 타스크가 참조할 기준 표는 `mydocs/tech/adapters_136M_summary.md`로 따로 둔다 (보고서에서 링크).

## 범위 외

- 어댑터 재학습, 270M 학습
- 스타일 특성 벡터 f(s,a), 방향 벡터 w_p, 지문 거리·혼동 행렬 (제안서 4.1~4.2, 6.3). 교차 평가는 모방 지표만 보며 스타일 분리의 증거로 내세우지 않는다
- α 스윕, 대국 성적 평가
- CUDA 오류 원인 규명 (보류)
- 소스 수정. 필요해지면 멈추고 따로 승인받는다

## 핵심 설계 원칙

- **수치는 스크립트로, 출처를 적는다**: 표의 값은 `log.jsonl`·`config.json`·실행 로그에서 스크립트로 뽑고, 기존 보고서의 값과 대조한다. 다르면 원인을 적는다.
- **비교 가능한 것만 비교한다**: val 세트가 기사마다 다르므로 절대값 순위는 매기지 않는다. 기준선 대비 변화와 같은 val에서의 교차 평가로 비교한다.
- **조건 차이를 숨기지 않는다**: 세 학습은 같은 코드·같은 설정이지만 재개 이력과 환경변수가 달랐다. 결과 표 옆에 함께 적는다.
- **가이드는 현재 코드 기준으로 쓴다**: Task #5 수정 후 코드(재개 동일성 성립, 옛 체크포인트 거부)를 기준으로 하고, 과거 이력은 짧게 남긴다.

## 결정 요청

1. 범위와 범위 외
2. **교차 평가(GPU 약 20분)를 넣을지**. 넣으면 "어댑터가 자기 기사를 더 잘 맞히는가"를 처음으로 확인할 수 있다. 빼면 GPU 없이 문서 작업만으로 끝난다
3. 기준 표를 `mydocs/tech/adapters_136M_summary.md`로 따로 두는 것
