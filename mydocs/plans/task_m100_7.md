# Task #7: 모델과 사용자가 직접 대국하는 체스 앱 개발 (유저 확인용) — 수행 계획서

## 수행 목표

학습한 모델(베이스, 기사별 LoRA 어댑터)과 사용자가 직접 체스를 두는 앱을 만든다. 사용자는 대국으로 각 어댑터의 기력과 기풍을 직접 느끼고, 모델이 어떤 후보를 얼마의 확률로 고려했는지 함께 본다.
지표(imitation, top1 등)로만 보던 어댑터를 실제 대국에서 확인하는 수단이다.

## 범위

1. **추론 엔진 모듈** (`src/play/engine.py`, 신규)
   - 모델 불러오기: 베이스(9M·136M·270M)와 136M 어댑터 세 개(탈·카르포프·스미슬로프). 베이스는 크기마다 한 번만 올리고, 어댑터는 LoRA 가중치만 바꿔 끼워 전환한다
   - 한 국면의 합법수 전체를 순전파 1회로 평가해 q(s,a)와 정책 π(a|s) = softmax(q/T)를 구한다. 학습 코드의 `encode_position`과 `policy_from_q`를 그대로 쓴다
   - 수 선택: **학습 정책 그대로 π(a|s)에서 샘플링한다 (T = 0.02, 학습 설정과 같음)** (작업지시자 결정)
   - 후보 수 상위 k개(SAN, π, q)를 돌려준다
   - 비교용: 같은 국면을 여러 모델(베이스 136M·탈·카르포프·스미슬로프)로 평가해 모델별 후보를 돌려준다
2. **로컬 웹 서버** (`src/play/server.py`, 신규, **FastAPI + uvicorn**) (작업지시자 결정)
   - `python -m src.play.server`로 실행하고, 브라우저에서 `http://localhost:8000`으로 접속한다
   - 대국 상태(국면, 수 기록)를 관리한다. 합법수 검증과 종료 판정(체크메이트, 스테일메이트, 기물 부족, 3회 반복, 50수 규칙)은 python-chess로 한다
   - JSON API: 모델 목록, 새 대국, 사용자 수, 모델 수, 무르기, 기권, 비교 평가, PGN 내보내기
   - 정적 파일(HTML·JS·CSS)도 같은 서버가 제공한다
   - `requirements.txt`에 `fastapi`, `uvicorn`을 추가한다 (이 타스크에서 늘어나는 의존성은 이 둘뿐이다)
3. **브라우저 화면** (`src/play/static/`, 신규, 직접 만든 HTML·JS·CSS, **lichess 디자인 참고**) (작업지시자 결정)
   - 배치는 lichess 대국 화면을 따른다. 가운데에 체스판을 두고, 오른쪽 패널에 상대(모델) 정보, 기보, 조작 버튼, 사용자 정보를 위아래로 놓는다. 어두운 배경 테마와 갈색 판으로 하고, 좁은 화면에서는 패널이 판 아래로 내려간다
   - 체스판: 클릭과 끌어 놓기로 수를 둔다. 선택한 기물의 합법수 점 표시, 마지막 수 칸 강조, 체크 표시, 승진 기물 선택 창, 사용자가 흑이면 판 뒤집기
   - 대국 설정 창 (lichess "컴퓨터와 대국" 형식): 모델, 사용자 색(백·흑·무작위)
   - 기보: 수 번호와 SAN을 2열 표로 보여 준다. 수를 누르면 그 국면을 보는 되돌려 보기를 지원한다
   - 정보 패널: 모델 차례마다 후보 수 상위 5개(π, q), 모델이 본 현재 국면의 예상 승률, 대국 결과
   - **비교 패널 (ON/OFF 토글)** (작업지시자 결정): 켜면 현재 국면에서 네 모델(베이스 136M·탈·카르포프·스미슬로프)의 후보 상위 수를 나란히 보여 준다. 끄면 계산하지 않는다. 설정은 브라우저에 기억한다
   - 무르기(사용자 수와 모델 수 한 쌍), 기권, 새 대국, PGN 저장
   - 기물 그림은 저작권 문제가 없는 공개 기물 세트(cburnett, CC BY-SA 3.0) SVG를 저장소에 넣고 출처를 적는다. 외부 CDN 없이 오프라인에서 돈다
   - lichess의 이름·로고 등 상표는 쓰지 않는다. 배치와 색감만 참고한다
4. **테스트**: 엔진과 서버 API를 pytest로 확인한다.
   - 엔진: 합법수만 고르는지, 시드를 고정한 샘플링이 재현되는지, π가 학습 코드의 값과 같은지, 어댑터 전환 전후 출력, 종료 국면 처리
   - 서버: FastAPI `TestClient`로 대국 진행, 불법수 거부, 무르기, 종료 판정, 비교 평가
   - 실제 가중치 없이 소형 무작위 모델로 돌린다 (기존 `tests/test_lora.py` 방식)
5. **실기 확인과 문서**: 실제 136M 베이스와 어댑터로 대국해 응답 시간과 GPU 메모리를 잰다. 비교 패널을 켰을 때와 껐을 때 둘 다 잰다. 실행 방법은 `mydocs/manual/play_app.md`에 쓰고, README에 한 절을 더한다

## 범위 외

- 모델끼리 자동 대국, Elo·대국 성적 평가 (제안서 6장, 후속 타스크)
- 외부 엔진(Stockfish) 분석, 대국 시계
- 원격 배포, 로그인, 여러 사용자 동시 접속. 로컬에서 한 사용자만 쓴다
- 학습·모델 코드 수정. 필요해지면 멈추고 따로 승인받는다

## 핵심 설계 원칙

- **학습과 같은 정책을 쓴다**: 앱의 확률과 수 선택은 학습·평가의 π(a|s)와 같은 함수(`policy_from_q`)와 같은 온도(T = 0.02)를 쓴다. 앱에서 보는 모델이 보고서의 모델과 같아야 확인 용도로 의미가 있다.
- **규칙 판정은 python-chess에 맡긴다**: 합법수와 종료 판정을 직접 구현하지 않는다. 행동 번호와 수의 대응도 기존 `src/model/actions.py`만 쓴다.
- **화면과 엔진을 분리한다**: 엔진은 웹과 무관한 순수 Python 모듈로 두어, 후속 타스크(모델끼리 자동 대국)에서 그대로 쓴다. 서버는 엔진을 감싸는 얇은 층으로 둔다.
- **화면은 의존성 없이 만든다**: 프론트엔드는 빌드 도구나 프레임워크 없이 순수 HTML·JS·CSS로 만든다. 체스 규칙은 서버가 판정하고, 브라우저는 서버가 준 합법수 목록만 쓴다.

## 기존 구현 현황

- `src/model/transformer.py`: `load_base`, `encode_position`(국면 → 합법수 전체 입력과 수 목록), `ActionValueTransformer.win_prob`(q)
- `src/model/lora.py`: `inject_lora`, `load_lora`, `load_adapter`
- `src/model/actions.py`: 행동 번호 사전, `ordered_legal_moves`
- `src/train/policy.py`: `policy_from_q`
- `base_model/{9M,136M,270M}.pt`, `runs/{tal,karpov,smyslov}_136M/adapter.pt` (git 제외, 로컬에 있음)
- 웹 프레임워크 미설치 (requirements: torch, chess, numpy, pytest). 설치 가능 버전: fastapi 0.162.0, uvicorn 0.54.0 (Python 3.13)
- 로컬 GPU: RTX 4070 Ti 12 GB (현재 사용 약 1.1 GB)

## 위험과 대응

| 위험 | 대응 |
|------|------|
| 모델은 FEN만 보고 수의 이력을 보지 않는다. 그래서 이긴 국면에서 3회 반복으로 비기는 수를 둘 수 있다 (원 논문도 지적한 한계) | 확인 용도이므로 모델 동작은 그대로 둔다. 반복 국면이 되는 수를 모델이 고르면 정보 패널에 표시하고, 보고서에 한계로 적는다 |
| 학습 정책 샘플링(T = 0.02)은 확률이 낮은 수도 가끔 고른다 | 의도한 동작이다 (학습 정책 그대로). 모델이 둔 수의 π를 기보 옆에 표시해, 낮은 확률의 수였는지 볼 수 있게 한다 |
| 비교 패널을 켜면 모델 차례마다 순전파가 4회로 늘어난다 | 어댑터 전환은 LoRA 가중치 교체뿐이라 136M 하나만 GPU에 둔다. 4단계에서 응답 시간을 실측한다 |
| 270M 베이스는 GPU 메모리를 더 쓴다 | 한 번에 한 베이스 크기만 GPU에 올리고, 크기를 바꾸면 이전 것을 내린다. 4단계에서 실측한다 |
| WSL2에서 연 서버에 Windows 브라우저가 붙지 않음 | WSL2 기본 localhost 전달을 쓰고, 안 되면 쓸 `--host 0.0.0.0` 옵션과 확인 방법을 매뉴얼에 적는다 |
| 어댑터 전환 시 LoRA 가중치가 섞임 | 전환 직후 출력이 그 어댑터만 단독으로 실은 모델의 출력과 같은지 테스트한다 |
