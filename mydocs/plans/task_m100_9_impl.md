# Task #9: 기풍 주입 평가 기준 작성 — 구현 계획서

## 공통

- 문서만 쓴다. 소스(`src/`, `scripts/`, `tests/`, `docker/`)는 수정하지 않고, 평가·학습·대국·LLM 호출을 실행하지 않는다.
- 산출물은 기준 문서 하나다. 단계마다 해당 절을 완성해 승인받는다.
- 값을 지금 정할 근거가 없는 항목은 "고정 시점"(어떤 측정으로, 언제, α > 0 결과 전)을 적고 비워 둔다. 근거 없이 숫자를 넣지 않는다.
- 판정 값은 단계마다 제안과 근거를 함께 내고 작업지시자가 정한다. 결정은 문서에 날짜와 함께 남긴다.
- 기준선 수치는 Task #6 문서(`mydocs/tech/adapters_136M_summary.md`, `mydocs/report/task_m100_6_report.md`)에서 옮기고 출처를 단다.

**산출물 위치**

```
mydocs/tech/evaluation_criteria.md          ← 기준 문서 (1단계 공통 규칙과 A, 2단계 B, 3단계 C, 4단계 D와 종합)
mydocs/working/task_m100_9_stage{1..4}.md   ← 단계별 완료 보고서
README.md                                   ← 4단계에 문서 표 링크 한 줄
```

**기준 문서 구성**

```
0. 문서 정보 (고정일, 정정 이력)
1. 연구 목표와 주장 A~D
2. 공통 규칙 (표본 분리, 통계, 구간 보고, 다중 비교, 기력과 동반, 기준 변경 절차)
3. 주장 A 재현
4. 주장 B 분리
5. 주장 C 기력
6. 주장 D 인과
7. 종합 판정 규칙
8. 학습 설계와 후속 입력 (R1~R10, gpu_train/ 요구 사항, 대국 수, 도구)
9. 제안서와 다른 점
10. 기준선 (Task #6, α = 0)
```

주장 절(3~6)은 모두 같은 형식으로 쓴다: 주장과 틀렸다고 볼 상황 → 채택 수단과 뺀 수단(이유) → 지표 정의(계산식, 입력, 표본, 집계 단위, 통계, 기준선) → 판정(통과·실패·판정 보류) → 고정 시점 → 기사 범위.

## 1단계: 문서 골격, 공통 규칙, 주장 A 재현

### 목표

기준 문서의 골격과 모든 주장에 쓰는 공통 규칙을 정하고, 주장 A의 판정 기준을 완성한다.

### 구현

1. **골격**: 위 구성으로 `mydocs/tech/evaluation_criteria.md`를 만든다. 1절(주장 A~D), 10절(기준선)을 채운다.
2. **공통 규칙 (2절)**
   - 표본 분리: 학습 신호로 스스로를 채점하지 않는다. w_p 추정 표본과 평가 표본을 나누는 방법(대국 단위 분할 비율)을 정한다
   - 통계: 대국 단위 부트스트랩의 반복 횟수, seed, 신뢰수준 (Task #6: 10,000회, seed 0, 95%)
   - 다중 비교: 세 기사와 여러 지표를 함께 판정할 때의 보정 방법 (예: Holm). 필수 지표에만 적용할지 정한다
   - 구간 보고: 전체와 ply 20 이상을 함께 보고한다. 판정에 쓰는 구간을 정한다
   - 기사 판정 규칙: 주장 하나가 "통과"하려면 세 기사가 모두 통과해야 하는지, 기사별로 따로 보고하는지
   - 기준 변경 절차: "정정" 기록 형식 (날짜, 이유, 바꾸기 전 기준의 판정)
3. **주장 A (3절)**
   - 필수: A1 수 일치, A2 오프닝 제외 일치, A3 불일치 국면 쌍대 비교, A5 특성 평균 이동, A6 특성 분포 거리
   - 보조: A4, A7, A8, A9′ / 선택: A9
   - 지표마다 계산식과 판정 조건을 적는다. 예: A1·A2는 "어댑터 − 베이스" top1 차이의 95% 구간 하한 > 0, A3은 McNemar 검정의 방향과 유의수준
   - A5·A6은 특성 정의에 좌우되므로 정의 확정 시점(특성 구현 이슈 완료 뒤, α > 0 학습 전)과 평가 표본(w_p 추정에 쓰지 않은 대국)을 적는다
   - A9′ 절차: 검증 관문 표본 수(기사당 대국 수), 통과 조건, 본 평가 표본 구성, 기록할 항목(모델 ID, 프롬프트, 응답 원문). 프롬프트와 모델은 실행 이슈에서 α > 0 결과 전에 고정한다고 적는다
   - α = 0 어댑터의 기준선이 있는 지표(A1, A2)는 Task #6 값을 연결한다

### 결정 요청 (단계 보고서에서)

- 다중 비교 보정 방법과 적용 범위
- 기사 판정 규칙 (세 기사 모두 통과 / 기사별 보고)
- A의 필수 지표별 판정 조건

### 검증

- A의 필수 지표마다 입력, 표본, 집계 단위, 통과·실패 조건이 있다
- 값을 못 정한 항목에 고정 시점과 방법이 있다
- Task #6 기준선 값이 출처와 함께 있다

## 2단계: 주장 B 분리

### 목표

B의 두 층(특성 없는 층, 특성 있는 층) 판정 기준을 완성한다. 카르포프의 방향 판정 수단을 정한다.

### 구현

1. **특성 없는 층**
   - B3 잡음 바닥: 거리 지표(같은 val 국면에서 π의 Jensen-Shannon 거리, 1순위 불일치율), 쌍 구성(기존 seed 0 + R1·R2·R8 seed 1), 판정 조건("다른 기사 쌍 거리 − 같은 기사 seed 쌍 거리"의 구간 하한 > 0 등). B3가 실패하면 B의 나머지를 판정 보류로 둔다고 적는다
   - B10 우도 혼동 행렬: 묶음 크기 k의 후보(val이 기사당 117~129국이므로 묶음 수가 충분한 범위), 판정에 쓰는 k, 우연 수준(1/3)과 비교하는 방법
   - B1: Task #6 값을 기준선으로 연결하고, 판정에 쓰지 않고 함께 보고하는 지표로 둔다
   - 스미슬로프-카르포프 쌍은 쌍별로 따로 판정한다
2. **특성 있는 층**
   - B8 복잡도 쌍대 검정: 국면 선택(두 모델의 1순위가 다른 국면), 복잡도 계산에 필요한 Stockfish 탐색 깊이는 특성 구현 이슈에서 정한다고 적고, 검정 방향(탈 > 스미슬로프)과 검정 방법을 정한다
   - B6 지문 혼동 행렬: 묶음 크기, 순환 방지(평가 표본 분리, α = 0 값과 비교)
   - **카르포프 방향**: "견고·질식"이 제안서 특성 4성분에 없으므로 다음 중 하나를 정한다
     - (a) B4 지문 순서("카르포프가 탈과 스미슬로프 사이", 제안서 6.3)로 판정한다
     - (b) 특성 구현 이슈에 카르포프용 성분 추가를 요구 사항으로 적는다
     - (c) 카르포프는 방향 판정 없이 특성 없는 층만 필수로 한다
3. 보조 수단(B2, B4, B5, B7, B9, B11, B12, B13)은 계산 방법과 보고 형식만 적는다.

### 결정 요청 (단계 보고서에서)

- B3·B10의 판정 조건과 k
- 카르포프 방향 판정 수단 (a/b/c)

### 검증

- 두 층 각각의 필수 지표에 판정 조건이 있다
- 순환 방지 조건(표본 분리)이 특성 있는 층 지표마다 있다
- B3 실패 시의 처리가 적혀 있다

## 3단계: 주장 C 기력

### 목표

대국 조건과 허용 기력 하락을 정하고, 주장 C의 판정 기준을 완성한다.

### 구현

1. **대국 조건 (C1·C2 공통)**: 수 선택 방식(π 샘플링 T = 0.02 또는 최선수), 오프닝 세트(출처, 개수, 색 교대 짝), 대국 수, 3회 반복·50수 처리, 최대 수 제한
2. **C1 베이스와 직접 대국**: Elo 차이와 95% 구간을 짝 단위로 집계하는 방법 (Fishtest 방식 참고). 허용 하락 한계와 근거(측정 오차, 대국 수로 얻는 구간 폭)
3. **C2 Stockfish 고정 상대**: 강도 제한 방식과 값, 비교 방법(어댑터와 베이스의 점수 차)
4. **C3 베이스 기준 regret**: Task #6 기준선(regret_top1 0.0027~0.0029), 단독 판정 불가 조건
5. **C4 Stockfish 기준 수 품질**: 탐색 깊이 또는 시간, 표본 크기, 큰 실수의 정의(손실 임계값)
6. 보조 수단(C5, C6, C7)은 계산 방법과 보고 형식만 적는다.
7. **대국 수 합산**: 어댑터 수(α = 0 3개, α > 0 6개, R7 1개)와 대국 조건으로 필요한 대국 수와 추정 시간을 적는다. 대국 시간은 Task #7 실기 응답 시간에서 어림하고 "추정"으로 표시한다
8. Stockfish 설치 위치(GPU 서버 또는 로컬)와 버전 고정을 요구 사항으로 적는다.

### 결정 요청 (단계 보고서에서)

- 수 선택 방식, 대국 수, 허용 Elo 하락 한계
- Stockfish 강도 제한 값과 C4 탐색 조건

### 검증

- C의 필수 지표(C1, C2, C3, C4)에 판정 조건이 있다
- 대국 조건이 실행기 구현에 추가 결정 없이 쓸 수 있을 만큼 정해져 있다
- 필요한 대국 수와 추정 시간이 있다

## 4단계: 주장 D 인과, 종합 판정, 문서 확정

### 목표

주장 D의 판정 기준과 연구 목표 전체의 종합 판정 규칙을 정하고, 후속 입력을 정리해 기준 문서를 고정한다.

### 구현

1. **주장 D (6절)**
   - D1 기력 항 ablation (탈, α*, R7 대 같은 α의 λ = 1)
   - D2 α 스윕 곡선: α 값(a₁, a₂)과 α* 선택 규칙의 고정 시점
   - D3 곡선 우위: R7의 스타일 발현이 λ = 1 곡선 구간 밖이면 판정 보류
   - D6 방향 통제 분석: 무작위 단위 벡터 수, seed, 판정 조건(w_p 코사인이 무작위 분포의 상위 몇 %)
   - D8 seed 변동 대비 효과: α = 0 seed 분산 가정과 그 한계
   - 비교군 조건: D의 비교는 현재 코드 어댑터(R1~R10)끼리 한다
2. **종합 판정 (7절)**: 주장 A~D 판정의 조합으로 연구 목표 전체를 판정하는 규칙. "실패"와 "판정 보류"를 구분하고, 실패도 결과로 보고하는 방식
3. **학습 설계와 후속 입력 (8절)**
   - R1~R10 표 (설정, 역할, 시점), 공통 설정
   - `gpu_train/` 요구 사항 (수행 계획서 표를 옮김)
   - 후속 이슈 목록과 순서: `gpu_train/` 작성 → R1·R2·R8 학습 → 특성 f(s,a)와 w_p 구현 → 대국 실행기 → R3~R7·R9·R10 학습 → 평가 실행
   - 필요한 도구와 자원: Stockfish, LLM API, 학습 시간 합계, 대국 수 합계
4. **제안서와 다른 점 (9절)**: 카르포프 필수, 지문 거리를 모델 지문 기준으로 판정, 인간 블라인드 평가 대신 AI 평가자, 순환 방지, 잡음 바닥, 기력 판정 보완 등 차이와 이유
5. **고정**: 0절에 고정일을 적는다. 이후 바꾸면 2절의 정정 절차를 따른다
6. `README.md` 문서 표에 기준 문서 링크를 한 줄 추가한다

### 결정 요청 (단계 보고서에서)

- 종합 판정 규칙
- D6 판정 조건

### 검증

- 수행 계획서 성공 기준 4개(주장 대응, 판정 가능성, 구현 가능성, 기준선)를 항목별로 점검한 표가 단계 보고서에 있다
- 문서 안의 수단 번호, 학습 ID, 절 참조가 서로 맞다
