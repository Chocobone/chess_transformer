# Task #13 최종 결과보고서: 대국 실행기 (Stockfish, 오프닝 세트, C1·C2·C4)

## 개요

평가 기준 문서 `mydocs/tech/evaluation_criteria.md` 5절(주장 C 기력)을 판정하는 데 필요한 도구를 만들었다.

| 도구 | 위치 | 하는 일 |
|---|---|---|
| 대국 실행기 | `src/match/` | 모델 대 모델(C1), 모델 대 Stockfish(C2) 대국 |
| 수 품질 도구 | `src/match/quality.py` | Stockfish 기준 수 품질(C4) |
| 집계·판정 | `src/eval/games.py` | C1·C2·C4 판정, C7 반복 비율, C2 노드 수 보정 |
| 서버 실행 틀 | `gpu_train/` | 대국·C4 작업 제출 |

기준 문서가 이 이슈에서 정하라고 남긴 값 네 가지를 α > 0 결과 전에 정정으로 고정했다.

- 오프닝 200개
- Stockfish 19
- C2 노드 수 300
- C4 깊이 18과 승률 변환식

이 도구로 α = 0 기준선을 쟀다. R1(탈)·R8(카르포프)·R2(스미슬로프) 모두 **C1·C2·C4를 통과**했다. Task #12의 C3와 합쳐 **α = 0 기준선의 C 판정(5.7절)은 통과**다. 수행 계획서의 끝 상태 네 가지에 모두 도달했다.

## 발견 사항

1. **대국에서는 어댑터가 베이스보다 강한데, 한 수 품질은 조금 나쁘다.**
   - C1(R8·R2)과 C2(세 모델)에서 어댑터가 베이스보다 유의하게 강하다 (+30~50 Elo).
   - C4에서는 손실이 +0.0014~0.0018 크고, 최선수 비율도 64.0% → 60.8~61.9%로 낮다.
   - 판정은 모두 통과지만 방향이 엇갈린다. 원인은 이번 자료로 가려지지 않는다. 후보는 세 가지다.
     - 국면 분포가 다르다 (기사 기보 국면과 모델이 만든 국면).
     - 한 수 품질과 대국 결과는 서로 다른 것을 잰다.
     - 날카로워진 정책이 표본 추출에서 덜 좋은 수를 덜 뽑는다.
   - α > 0 평가에서 같은 엇갈림이 나오는지 함께 본다.
2. **기보 재현에는 같은 torch 버전이 필요하다.**
   - 장비가 서버 GPU(A2000, 2080 Ti)든 로컬 CPU든 같은 seed로 기보가 같았다. 동시 대국 수를 64에서 24로 바꿔도 같았다.
   - 그러나 torch 2.15에서는 π가 같아도 `torch.multinomial`이 같은 seed에서 다른 수를 뽑는다.
   - α > 0 대국은 기준선과 같은 torch 2.5.1(서버 지금 환경)로 두어야 같은 조건이다.
3. **판당 ply가 추정(80)의 2~3배다.** C2는 175~201 ply, C1은 227~238 ply이고, C1의 15~16%가 400 ply 한도로 끝났다. 모델이 이긴 국면을 마무리하지 못하는 일이 많다는 뜻이다. 대국 시간 추정이 늘어난 주된 이유다.
4. **C4의 ℓ < 0 자르기가 최선수가 아닌 수의 19~22%다.**
   - 깊이 18 단일 탐색의 불일치가 흔하다.
   - 자르지 않아도 차이는 같아서 판정에는 영향이 없다.
5. **서버 환경 제약 세 가지**
   - glibc가 낮아 Stockfish를 정적 빌드했다 (4단계 보완).
   - A2000(6 GB)에서는 동시 64국이 OOM이라 동시 24국으로 돌렸다.
   - GPU를 요청하지 않는 작업은 QoS가 CPU 1개로 제한한다. 그래서 C4를 GPU 작업으로 냈다.
   - 세 가지 모두 소스 수정 없이 실행 옵션으로 대응했다.
6. **실측 소요**
   - C2 400국 1.4~1.7시간 (A2000), C1 400국 약 1.5시간 (2080 Ti), C4 모델 4개 1.0시간 (CPU 4개)
   - α = 0 기준선 2,800국에 10.9시간이 걸렸다.
   - 8,700국 전체는 약 32시간으로 다시 추정했다 (기준 문서 5.6절 정정).
