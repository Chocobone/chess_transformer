## 1. 실행 명령

`train.sbatch`가 `gpu_train/runs.py`로 만든 명령이다 (작업 기록의 `명령:` 줄). 학습마다 다른 것은 `--player`, `--out`뿐이다.

```
python -u -m src.train.train --player tal --out runs/gpu/R1 --base base_model/136M.pt --rank 16 --lora-alpha 32 --lr 1e-4 --epochs 3 --batch-positions 32 --temperature 0.02 --tau 0.02 --gamma 0 --eval-every 1000 --checkpoint-every 200 --num-workers 2 --alpha 0.0 --lam 1.0 --seed 1 --resume
```

| 학습 | `--player` | `--out` |
|---|---|---|
| R1 | `tal` | `runs/gpu/R1` |
| R2 | `smyslov` | `runs/gpu/R2` |
| R8 | `karpov` | `runs/gpu/R8` |

- **평가 1회 시간**: eval 직후 20 step의 `elapsed` 증가에서 직전 20 step의 증가를 빼서 추정했다. step 1,000, 2,000, …의 중간 평가에서 쟀다. val 국면 수에 거의 비례한다(초당 약 5.4~5.6국면).
- 작업 전체와 마지막 `elapsed`의 차이(12~16분)는 대부분 baseline과 마지막 평가다.
- 로컬 RTX 4070 Ti(학습 가이드·`gpu_train/README.md` 7절)와 비교하면 다음과 같다.
  - 학습 1회: 로컬 약 3.1~3.6시간 → 서버 7.9~10.1시간, **약 2.5~2.8배**
  - 처리량: 로컬 약 25국면/초 → 서버 약 10.5~10.8국면/초
  - 평가 1회: 로컬 약 3분 → 서버 12~16분, 약 4~5배. 평가는 float32다(`eval_amp` false). 학습보다 차이가 큰 이유는 확인하지 않았다. 평가(중간 + 마지막, 1회 시간 × 횟수)가 작업 전체 시간의 약 20%(R1)·23%(R2)·26%(R8)를 차지한다
- 메모리는 6 GB GPU 안에 들었다(GPU 전체 최대 4.90 GiB). 기준 문서 8.1절의 "학습 1회 7.86 GiB"는 로컬 RTX 4070 Ti에서 데스크톱을 포함한 GPU 전체 사용량이다(Task #4). 서버 값이 더 작은 이유(torch 2.5.1 대 로컬 버전, 데스크톱 유무 등)는 확인하지 않았다.

## 8. 서버 재평가 (`gpu_train/eval_adapter.py`, `eval.sbatch`)

작업지시자가 GPU 서버에서 실행했다 (2026-11-12). 작업이 두 번 제출됐고(219156, 219171), 두 출력은 시각과 소요 시간만 다르고 수치와 판정이 같다.

- 처음에는 로컬 GPU에서 재평가할 계획이었다. 이 작업 사본의 PC(Ryzen 7 7840U, Radeon 780M)에는 NVIDIA GPU가 없고, RTX 4070 Ti PC에서도 하지 않기로 했다. 그래서 GPU 서버에서 평가한다 (작업지시자 결정, 2026-11-10)
- 판정: top1·top3는 정확히 같고, 나머지는 |차이| < 5 × 10⁻⁵ (서버 smoke와 같은 규칙)
- 대상은 R1·R2·R8뿐이다. 학습과 평가가 같은 서버이므로 장비 사이의 일치는 확인하지 않는다 (작업지시자 결정)

## 짚어 둘 점

1. **서버 평가가 느리다.** 평가 1회가 12~16분으로 로컬의 4~5배다. 남은 7회에서도 평가에 약 14시간이 든다(기사별 평가 1회 시간 × 횟수). `--eval-every`를 늘리면 줄일 수 있지만 학습 설정(8.1절의 학습 기록 형식)이 바뀌므로 이번 타스크에서는 다루지 않는다. 필요하면 α > 0 학습 이슈에서 정한다.
2. **서버의 미커밋 변경** `gpu_train/site.env.example`은 Task #10과 같다. 이월 항목으로 남긴다.
3. **서버 GPU 노드가 두 종류다.** seed 0 학습 일부가 RTX 2080 Ti 노드(`moana-u8`)에 배정됐다. 이 노드는 학습이 약 2.7배 느리고(9.5절), 카르포프 1회가 20시간 제한을 넘는다. 남은 α > 0 학습에서 장비를 맞추려면 A2000 노드로 고정하는 것이 좋다. 고정 방법(Slurm `--nodelist`, `--constraint` 등)은 α > 0 학습 이슈에서 정한다.
4. **R8s0이 시간 제한에 걸려 이어서 제출로 끝났다.** 재개는 기록상 정상이다(9.2절). 겹친 step 8,620~8,720은 다른 GPU에서 다시 학습됐다.
