- 상태: 원인 확인, 영향 추정 완료. 수정은 Task #5 2단계 (작성 중)

## 증상

실행 로그(`runs/logs/train_{player}_136M.log`)에는 실패한 시도와 재개한 시도의 train 줄이 모두 남아 있다. 같은 step끼리 비교하면 lr은 같지만 loss·grad_norm이 다르다. 재개한 학습은 같은 체크포인트(같은 가중치, 같은 옵티마이저 상태)에서 출발했으므로, 같은 배치였다면 GPU 비결정성 정도의 차이만 나야 한다.

| 기사 | 재개 지점 | 겹치는 구간 | 예 (step: 실패한 시도 / 재개한 시도) |
|------|------|------|------|
| 탈 | 4800 (epoch 1) | 4820~5000 | 4820: loss 0.7709 / 0.9388, 5000: 1.3635 / 0.6882 |
| 스미슬로프 | 5400 (epoch 1) | 5420~5580 | 5420: loss 1.4239 / 1.0175, 5540: 0.7415 / 1.2585 |
| 카르포프 | 6000 (epoch 1), 6200 (epoch 2) | 없음 (체크포인트 직후 종료) | — |

## 원인

`src/train/train.py`는 데이터 순서용 생성기 `generator` 하나를 `RandomSampler`와 `DataLoader(generator=...)`에 함께 넘긴다. `DataLoader`는 반복자를 새로 만들 때 이 생성기에서 worker 시드를 하나 뽑는다.

- 본 학습은 `num_workers=2`라서 `persistent_workers=True`다. 반복자는 프로세스에서 처음 한 번만 만들어진다. epoch 0에는 "worker 시드 → 순열"을 뽑고, epoch 1부터는 순열만 뽑는다.
- 재개한 프로세스는 체크포인트에 저장된 "그 epoch를 시작할 때의 생성기 상태"를 복원한 뒤 반복자를 새로 만든다. 그래서 worker 시드를 한 번 더 뽑고, 순열이 밀린다.
- 결과: 재개한 epoch에서는 다른 순열의 앞부분(이미 끝낸 배치 수만큼)을 건너뛴 나머지를 학습한다. 생성기 상태가 밀린 채 이어지므로 그다음 epoch들의 순열도 끊기지 않은 학습과 다르다. 다만 이 epoch들은 국면마다 한 번씩 빠짐없이 학습한다.
- `num_workers=0`이면 epoch마다 반복자를 새로 만들므로 끊기지 않은 학습도 매 epoch 시드를 뽑는다. 재개해도 순서가 같다. 기존 재개 테스트(`--num-workers 0`)와 Task #2의 GPU 재개 검증(epoch 0 안에서만 끊음)은 그래서 이 문제를 잡지 못했다.
- 같은 이유로 끊기지 않은 학습도 `num_workers`가 0이냐 2냐에 따라 epoch 1부터 순서가 다르다. 그런데 `--num-workers`는 재개 때 바꿔도 되는 인자로 되어 있다.

### 확인 방법

수정 전 코드의 `ResumableBatchSampler`와 실제 `DataLoader`를 써서, 학습 루프의 순서 관련 부분만 옮긴 시뮬레이션을 CPU에서 돌렸다. 모델 대신 배치 인덱스만 모은다. 데이터 4,000개, 배치 32(epoch당 125 배치), 3 epoch로, step 200(epoch 1)과 260(epoch 2)에서 재개한 결과는 아래와 같다.

| `num_workers` | 끊기지 않은 학습과 다른 배치 수 (epoch 0 / 1 / 2) |
|---|---|
| 0 | 0 / 0 / 0 |
| 2 | 0 / 50 / 125 |

epoch 1에서 한 번만 재개해도 `num_workers=2`에서는 0 / 50 / 125였다. 재개 지점 뒤의 epoch 1 나머지 50 배치와 epoch 2 전체가 다르다.

## 세 어댑터가 받은 영향

실제 데이터 크기와 시도 기록(배치 32, seed 0, 3 epoch, `num_workers=2`)으로 같은 시뮬레이션을 돌려, 체크포인트까지 남은 갱신에 쓰인 국면만 셌다. 계획은 국면마다 epoch당 1회, 합계 3회다.

| 기사 | 국면 수 | 재개 | 재개한 epoch에서 2회 / 0회 학습된 국면 | 3 epoch 합계 횟수 분포 |
|------|------|------|------|------|
| 탈 | 79,493 | step 4800 (epoch 1, 2,315/2,485 배치 뒤) | epoch 1: 5,045 / 5,045 (6.35%) | 2회 5,045, 3회 69,403, 4회 5,045 |
| 카르포프 | 96,393 | step 6000 (epoch 1, 2,987/3,013 뒤), 6200 (epoch 2, 174/3,013 뒤) | epoch 1: 801 / 801 (0.83%), epoch 2: 5,279 / 5,279 (5.48%) | 1회 52, 2회 5,895, 3회 84,487, 4회 5,919, 5회 40 |
| 스미슬로프 | 93,178 | step 5400 (epoch 1, 2,488/2,912 뒤) | epoch 1: 11,597 / 11,597 (12.45%) | 2회 11,597, 3회 69,984, 4회 11,597 |

- 갱신 수, 학습률 일정, 학습한 국면의 총량은 계획과 같다. 달라진 것은 어떤 국면을 몇 번 보았는지와 배치 순서다.
- 성능 영향은 실측하지 않았다 (작업지시자 결정, 2026-10-15). 재개 뒤 val 지표는 계속 좋아졌다.
- 세 어댑터는 같은 조건의 "끊기지 않은 학습" 결과가 아니다. 결과를 종합할 때 이 차이를 적는다.

## 남은 한계

- 시뮬레이션은 순서 관련 루프를 옮긴 것이다. 실제 학습의 배치 내용은 로그에 남아 있지 않아 직접 대조하지 못했다. 겹치는 step의 loss가 다르다는 점만 시뮬레이션과 맞는다.
