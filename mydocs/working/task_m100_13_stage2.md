# Task #13 단계2 완료 보고서: 대국 실행기

## 수행 내용

- **묶음 정책** `src/match/policy.py`의 `PolicyBank`를 만들었다. 대국 앱 `Engine`과 같은 방식으로 136M 베이스를 한 번 올리고 LoRA를 한 번 주입한 뒤, 모델마다 LoRA 가중치만 바꿔 끼운다(`base`는 LoRA 0). π는 `legal_action_tokens` → `win_prob` → `policy_from_q`(T = 0.02)로 계산하고, 샘플링은 `torch.multinomial`로 한다. 둘 다 대국 앱과 같다. 국면 여러 개를 묶어 계산하며, 줄 수가 `max_rows`(8,192)를 넘으면 국면 단위로 나눈다.
- **대국 상태** `src/match/game.py`
  - `GameSpec`: 오프닝, 평가 대상, 상대, 색. seed = 2 × 오프닝 + 색(해석 2)
  - `pair_specs`: 오프닝마다 평가 대상이 백인 대국과 흑인 대국을 순서대로 만든다
  - `MatchGame`: 대국마다 생성기 하나를 둔다(C1에서는 두 모델이 차례로 같은 생성기를 쓴다). 종료 판정, 평가 대상 쪽 점수, PGN을 맡는다
  - 종료 규칙은 대국 앱 `Game.outcome`과 같고, 400 ply 한도(오프닝 8 ply 포함, 해석 1)를 더했다
- **동시 대국** `src/match/runner.py`
  - 한 바퀴마다 모델 차례 국면을 모델별로 묶어 계산한다. Stockfish 차례 국면은 별도 스레드에서 프로세스 풀(`StockfishPool`)에 나눠 모델 계산과 겹치게 한다
  - 끝난 대국마다 `games.pgn`과 `index.jsonl`에 한 판씩 덧붙인다. 다시 실행하면 끝난 대국을 건너뛴다. 실행 기록은 `runs.jsonl`에 실행마다 한 줄씩 남는다
- **CLI** `src/match/play.py`: `python -m src.match.play --model R1 --opponent base|sf [--nodes N] --openings 0-199 --out DIR`. 첫 실행 때 `config.json`(모델, 상대, 노드 수, 오프닝 파일, 베이스)을 쓰고, 다시 실행할 때 설정이 다르면 거부한다.

### PGN 기록 (한 판)

`FEN`·`SetUp`(오프닝 국면), `White`·`Black`(모델 ID 또는 `sf`), `Result`, `Opening`, `ModelColor`, `Seed`, `Termination`, `PlyCount`(오프닝 뒤 수), `TotalPly`(오프닝 포함), `WhiteSha256`·`BlackSha256`(어댑터 또는 베이스 파일), `Concurrent`, Stockfish 상대면 `Engine`·`EngineSha256`·`Nodes`·`EngineThreads`·`EngineHash`. 모델이 둔 수에는 `{pi=…}` 주석으로 π를 남긴다.

## 발견 사항

1. **Stockfish 1만 노드는 베이스에 비해 너무 강하다.** 시험 10국에서 베이스 점수율이 0이었다. 해석 6의 예비 보정 후보(1천·3천·1만·3만·10만 노드) 중 위쪽 세 개는 0.35~0.65 범위에 들 가능성이 낮다. 결과를 보기 전에 정하는 값이므로, **후보를 낮은 쪽으로 옮기는 것을 결정 요청한다** (아래). 이 시험은 베이스만으로 한 것이고 판정에 쓰지 않는다. 기준 문서 5.4절의 보정 절차(베이스만으로 노드 수를 고른다)를 벗어나지 않는다.
2. **로컬 CPU로는 136M 대국이 너무 느리다.** 바퀴당 약 9초이며, Stockfish와 torch가 같은 CPU를 나눠 쓴다. 실제 대국은 계획대로 서버 GPU에서 한다. 서버 속도는 4단계 예비 보정에서 잰다.
3. **`runs.jsonl`의 `sf_seconds`는 모델 계산과 겹친 시간을 포함한다.** Stockfish를 별도 스레드에서 돌리기 때문이며, 실제 Stockfish 작업 시간이 아니라 Stockfish 차례를 기다린 바퀴의 벽시계 시간이다. 보고할 때는 전체 `seconds`와 `model_seconds`를 쓴다.
4. **진행 중이던 대국은 이어서 실행할 때 처음부터 다시 둔다.** 테스트(CPU)에서는 끊었다가 이어서 둔 기보가 한 번에 둔 기보와 같았다. GPU에서는 묶음 구성이 달라지면 부동소수점 차이로 드물게 수가 갈릴 수 있다(해석 10). 그런 경우는 6단계 재현 확인에서 보고한다.

- 권장: **100·300·1천·3천·1만**으로 바꾼다. 본 보정 규칙(3개 × 100국, 0.5에 가장 가까운 값)과 추가 보정 규칙은 그대로 둔다. 1만에서 0/10이었으므로, 점수율 0.5 근처는 그보다 한두 자릿수 아래에 있을 것으로 본다
