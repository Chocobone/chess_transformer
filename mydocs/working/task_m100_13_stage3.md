# Task #13 단계3 완료 보고서: C4 수 품질 도구, 집계·판정

## 수행 내용

### C4 수 품질 탐색 `src/match/quality.py` (서버, CPU)

- **입력 확인**: Task #12 덤프(`positions.npz`)와 val 기록(`data/processed/{기사}/val.jsonl`)에서 국면 FEN을 읽는다. 기사 순서·대국·ply·국면 수가 덤프와 같은지 확인한다.
- **모델 1순위 수**: 각 모델 덤프의 log π에서 `metrics.segment_argmax`로 고른다(Task #12와 같은 규칙). 국면마다 합법수 수가 덤프와 같은지 확인한 뒤 `ordered_legal_moves`로 UCI 수에 대응시킨다.
- **탐색 (해석 8)**
  1. 국면마다 최선수를 고정 깊이로 한 번 탐색한다
  2. 모델 1순위 수가 최선수와 다르면 그 수만 허용해 한 번 더 탐색한다. 같은 (국면, 수)는 모델이 여럿이어도 한 번만 탐색한다
  3. 손실 ℓ = W(최선수) − W(모델 수)이고, W는 둘 차례 쪽 기준이다. 탐색 불일치로 ℓ < 0이면 0으로 자르고 기록한다
- **캐시**: `best.jsonl`, `moves.jsonl`에 탐색이 끝나는 대로 한 줄씩 덧붙인다. 다시 실행하면 새 (국면, 수)만 탐색한다. 다른 깊이의 캐시와 섞이지 않도록 `config.json`(덤프, 깊이)이 다르면 거부한다.
- **결과**: 모델마다 `{모델}.npz`(국면별 손실, 최선수 여부, 자름 여부), 그리고 `quality.json`(Stockfish 버전·SHA-256, 모델별 요약, 시간)을 남긴다.
- **병렬**: Stockfish 프로세스 풀을 스레드로 나눠 쓴다. 매 탐색 전에 해시를 비우므로 어느 프로세스가 맡든 결과가 같다.

### 집계·판정 `src/eval/games.py` (numpy만)

| 함수 | 내용 |
|---|---|
| `pair_scores` | `index.jsonl` → 오프닝별 짝 점수(0~2). 짝이 다 차지 않았거나 같은 대국이 두 번 있으면 거부 |
| `elo` | Elo = −400·log₁₀(1/s − 1), s는 [0.001, 0.999]로 자름 (해석 4) |
| `c1` | 짝 부트스트랩(10,000회, seed 0) 점수율·Elo 구간. 하한 > −50 통과, 상한 < −50 실패. 승·무·패, 종료 사유, 평균 ply 보고 |
| `c2` | 같은 뽑기 행렬로 어댑터 짝·베이스 짝을 함께 뽑아 Elo 차이 구간 (해석 5). 오프닝이 다르면 거부 |
| `c4` | (어댑터 − 베이스) 평균 손실 차이. S_val 전체, 기사별 층화 대국 부트스트랩 (해석 9, Task #12 B2와 같은 뽑기). 상한 < 0.02 통과, 하한 > 0.02 실패. ply ≥ 20, 큰 실수(ℓ ≥ 0.20) 비율 차이, 기사별 값 보고 |
| `c7_repetition` | 3회·5회 반복으로 끝난 대국 비율 |
| `calibrate` | 보정 폴더들 → 노드 수별 점수율, 선택(0.35~0.65 중 0.5에 가장 가까움, 같으면 작은 쪽), 본 보정 후보 3개 제안, 범위 안이 없을 때의 추가 노드 수(기하 평균) (해석 6) |
| `judge`, `report` | `C1_{모델}`, `C2_{모델}`, `C2_base` 폴더와 C4 결과 → `results.json`, `report.md` |

CLI는 `python -m src.eval.games judge …`와 `python -m src.eval.games calibrate …`다.

## 발견 사항

1. **보정 선택에서 부동소수점 거리 문제가 있었다.** 점수율 0.55와 0.45의 0.5까지 거리가 부동소수점으로는 다르게 나와, "같으면 작은 노드 수" 규칙이 깨졌다. 거리를 소수 9자리로 반올림해 비교하도록 고쳤다. 점수율은 k/(2 × 짝 수)라 이 정도 반올림으로 다른 값이 같아지지 않는다.
2. **C4 탐색에는 서버에 val 기록(`data/processed/`)이 필요하다.** 이 PC에는 val 기록이 없다. 서버에는 Task #12 덤프 때 쓴 입력이 있다. 그래서 실제 S_val 탐색은 서버에서만 할 수 있고, 로컬에서는 가짜 덤프와 실제 Stockfish로 확인했다.
3. 실제 Stockfish 짧은 확인(깊이 12): 중반 국면의 최선수 d2d3(+24cp, W 0.522), 허용 수 h2h4(−115cp, W 0.396)로 손실 0.126이었다. 1수 메이트 국면은 최선수 a1a8, W 1.0이었다. 점수 기록과 승률 변환이 맞게 이어진다.
