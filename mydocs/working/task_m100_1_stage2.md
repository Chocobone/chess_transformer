# Task #1 단계2 완료 보고서: 베이스 모델 PyTorch 이식 및 가중치 로드·검증

## 수행 내용

searchless_chess action-value Transformer를 PyTorch로 이식하고, 원본 체크포인트를 PyTorch 가중치로
바꾸는 변환 경로와 원본 출력과의 수치 비교 스크립트를 작성했다. 원본 소스(`tokenizer.py`, `utils.py`,
`transformer.py`, `engines/neural_engines.py`, `engines/constants.py`, `training_utils.py`)를 줄 단위로 읽고 맞췄다.

작업지시자 지시에 따라 원본 저장소를 로컬 컨테이너에서 직접 실행해 수치를 비교했고, **9M·136M·270M 모두 완료 조건을 통과했다.** 컨테이너에 GPU가 연결되어 있지 않아 비교는 CPU로 수행했다.

## 원본 대조로 확정한 세부 사항

- **입력 shift**: 원본은 79토큰 `[FEN 77, 행동, 리턴 자리]`를 오른쪽으로 한 칸 밀어 `[0, FEN 77, 행동]`을 넣는다. 마지막 리턴 토큰은 버려지며, 마지막 위치의 출력이 승률 구간 분포다.
- **임베딩 공유**: FEN 토큰(0~30)과 행동 토큰(0~1,967)이 같은 임베딩 표(1,968행)를 쓴다.
- **bias**: 어텐션 q/k/v/출력 투영과 MLP 세 선형층은 bias가 없고, 최종 출력 선형층만 bias가 있다.
- **LayerNorm**: scale과 offset이 있고 eps는 1e-5로 PyTorch 기본값과 같다.
- **가중치 종류**: 원본 엔진은 EMA가 아닌 `params`를 쓴다. 내보내기 스크립트도 기본값을 `params`로 했다 (`--ema` 옵션 제공).
- **합법수 순서**: 원본 엔진은 합법수를 행동 번호 순으로 정렬한다. 같은 순서를 쓴다.

## 발견 사항

1. **체크포인트는 numpy만으로 읽을 수 없다**: 계획서는 "Haiku 파라미터 트리를 numpy로만 읽어" 변환한다고 했으나, 실제 체크포인트는 orbax(OCDBT) 형식이라 orbax가 필요하다. 변환을 두 단계로 나눴다. (1) JAX 환경에서 `export_haiku_params.py`로 npz 추출 → (2) `convert.py`로 PyTorch 변환. 학습 코드에는 JAX 의존성이 남지 않는다.
2. **원본 실행 환경**: 원본 저장소(커밋 `90ae0e6`)와 9M·136M·270M 체크포인트를 세션 임시 폴더에 내려받고, 임시 가상환경(jax, dm-haiku, orbax-checkpoint, apache-beam, grain 등)에서 실행했다. 프로젝트 환경과 저장소에는 영향이 없으며, 컨테이너를 재생성하면 사라진다. 변환된 가중치(`base_model/*.pt`)와 기준 출력(`base_model/reference_*.npz`)은 저장소 폴더에 남는다 (git 제외 대상).
3. **GPU 미연결 (이후 해결)**: 처음 비교할 때 이 컨테이너에는 호스트 GPU가 연결되어 있지 않았다 (`nvidia-smi` 없음, `torch`는 CPU 빌드). 비교는 CPU로 충분해 그대로 진행했다. GPU 연결을 위해 `docker/compose.yml`에 GPU 예약을 추가하고 `Dockerfile`의 `torch`를 CUDA 포함 휠로 바꿨으며, 작업지시자가 컨테이너를 재생성한 뒤 GPU가 정상 인식됨을 확인했다 (`torch.cuda.is_available()` True).
4. **파라미터 수**: 9M 체크포인트는 텐서 94개, 8,954,240개로 이식 모델과 정확히 일치한다. 136M은 텐서 94개 136,479,872개, 270M은 텐서 182개 270,730,368개로 역시 실제 체크포인트와 정확히 일치한다.
5. **로그확률 오차의 성격**: 같은 PyTorch 모델도 배치 크기에 따라 로그확률이 최대 1.9e-5 달라진다 (확률이 사실상 0인 구간에서 로그값이 커져 오차가 부풀려진다). 원본과의 실제 오차는 4.6e-5 ~ 6.5e-5로 목표 1e-4 안에 들어왔다. `verify_port.py`는 구간 확률 오차와 승률 오차도 함께 출력한다.

## 검증

- `pytest`: 67 passed, 0 failed (환경 6 + 전처리 38 + 모델 23)
  - 토큰화: 시작 국면 77토큰 전체, 앙파상·부분 캐슬링·3자리 카운터의 손계산 값과 일치
  - 행동 공간: 크기 1,968, 처음·끝 번호의 수, 프로모션 176개, 대표 수 왕복 변환
  - **변환 + 모델 수식**: 무작위 Haiku 형식 파라미터를 변환한 PyTorch 모델의 출력이, 원본 수식을 Haiku 파라미터 이름 그대로 numpy로 옮긴 기준 구현과 1e-4 이내로 일치
