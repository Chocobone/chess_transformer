## 발견 사항

1. **val 평가 1회는 약 2.4~3.2분이다.** 평가는 캐시 생성과 같은 계산(float32, 합법수 256개 묶음)이라 캐시의 val 시간이 곧 평가 시간이다: 탈 142초, 카르포프 190초, 스미슬로프 172초. 확인 학습의 전체 실행 시간 249초도 이 값과 맞는다 (60 갱신 80초 + 평가 약 142초 + 로드·기준선 약 27초). 평가 시간만 따로 잰 것은 아니다.
2. **갱신 횟수가 계획서 값과 조금 다르다.** 계획서는 국면 수 × 3 ÷ 32로 계산했는데, 실제로는 epoch마다 마지막의 작은 배치도 한 번의 갱신이라 탈 7,455 / 카르포프 9,039 / 스미슬로프 8,736이다 (계획서 7,452 / 9,037 / 8,735). 평가 횟수(8 / 10 / 9회)는 그대로다.
3. **처리량과 메모리는 Task #1의 실측과 같다.** 캐시 약 888 수/초(Task #1 약 880), 학습 갱신당 1.33초(약 1.3초), 최대 메모리 4.61 GiB(약 4.7 GiB).
4. **캐시의 q 범위는 [0.003906, 0.996094]다.** 양 끝은 128개 승률 구간 중 첫 구간과 마지막 구간의 중심값(1/256, 255/256)이다. 모델 출력의 구조상 한계이며 이상이 아니다.
5. **캐시 스크립트는 split이 끝날 때만 출력한다.** 한 기사에 50~60분 동안 진행률이 보이지 않는다. 이번에는 고치지 않았다.
