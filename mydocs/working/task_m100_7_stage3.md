## 3. 동작

**체스판** (`board.js`)
- CSS 그리드 8×8에 기물 `<img>`를 놓는다. 클릭 두 번(기물 → 칸)과 끌어 놓기를 둘 다 받는다. 서버가 준 `legal_moves`에 있는 수만 받는다.
- 승진 수면 판 위에 퀸·룩·비숍·나이트 선택 창을 띄운다.
- 사용자가 흑이면 판을 뒤집는다. 가장자리에 a~h, 1~8 좌표를 적는다.
- 기물 이동에 0.15 s 애니메이션을 준다.

**흐름** (`app.js`)
1. 처음 열면 `GET /api/models`, `GET /api/game`을 부른다. 진행 중인 대국이 없으면 설정 창(모델 목록, 백·무작위·흑 버튼)을 띄운다. 있으면 이어서 둔다. 모델 차례면 바로 모델 수를 요청한다.
2. 사용자 수 → `POST /api/game/move` → 대국이 끝나지 않았으면 `POST /api/game/engine`. 기다리는 동안 모델 쪽에 "생각 중"을 띄우고 무르기·기권을 막는다.
3. 대국이 끝나면 판 위 결과 창(예: "0-1 · 흑 승 · 체크메이트")과 기보 끝에 결과를 보인다. 결과 창은 닫을 수 있다.
4. 무르기(`⟲`), 기권(`⚑`), PGN 저장(`↓`, `/api/game/pgn` 내려받기).

**기보**: 수 번호와 백·흑 SAN의 2열 표다. 모델 수에는 π를 붙인다 (`c5 72%`). π가 10% 미만이면 `--low` 색으로 표시한다. 3회 반복을 만든 수에는 표시를 붙인다.

**되돌려 보기**: 기보의 수를 누르거나 ⏮ ◀ ▶ ⏭ 버튼, 키보드 ←/→로 지난 국면을 본다. 국면은 서버가 준 각 수의 `fen`으로 그린다 (화면에서 규칙을 다시 구현하지 않는다). 지난 국면을 보는 동안에는 입력을 막는다.

**후보 수 패널**: 보고 있는 국면까지 모델이 마지막으로 둔 수의 후보 상위 5개를 보인다 (SAN, π 막대, q). 실제로 둔 수는 강조한다. 되돌려 보기 중에도 그 시점의 후보가 나오도록 각 수의 `analysis`를 쓴다 (5절 1).

**비교 패널**
- 상단 바 토글로 켜고 끈다. 상태는 `localStorage`(`chess-app.compare`)에 둔다. 저장소 접근은 모두 `try/catch`로 감쌌다. 저장소를 못 쓰면 기본값 OFF로 동작한다.
- 켜면 보고 있는 국면에서 `POST /api/analyze`를 불러 네 모델(베이스 136M·탈·카르포프·스미슬로프)의 상위 3수와 승률을 열로 보인다. 그 국면에서 실제로 둔 수는 강조한다.
- 같은 FEN의 결과는 화면에 캐시한다. 되돌려 보기로 오갈 때 다시 계산하지 않는다. 늦게 도착한 이전 요청의 응답은 버린다.
- 끄면 `/api/analyze`를 부르지 않는다. 종료 국면에서는 "종료 국면입니다"를 띄운다.

## 4. 검증

```
$ python -m pytest -q
142 passed, 57 warnings in 43.97s
```

화면 코드는 계획대로 자동 테스트하지 않는다. 서버 테스트 `test_play_a_game`에 각 수의 `analysis` 확인 1줄을 더했다 (모델 수 = `last_analysis`, 사용자 수 = 없음). 그래서 테스트 수는 2단계와 같다.

실제 가중치 서버 (GPU):

```
$ python -m src.play.server --host 0.0.0.0
INFO:     Uvicorn running on http://0.0.0.0:4321
```

- 컨테이너 안에서 `GET /`, `GET /api/models`(모델 6개), 기물 SVG 모두 200이다.
- 작업지시자가 Windows 브라우저(`http://localhost:4321`)로 서버 동작을 확인했다 → 승인.

화면 캡처는 넣지 않았다. 컨테이너에 헤드리스 브라우저가 없어 직접 찍을 수 없고, 작업지시자 캡처도 받지 않았다. 4단계 매뉴얼을 쓸 때 캡처가 있으면 넣는다.

## 5. 계획과 다른 점

1. **각 수의 `analysis`를 상태에 추가** (`game.py`): 2단계 상태는 마지막 모델 수의 분석(`last_analysis`)만 주었다. 되돌려 보기 중에 그 시점 모델의 후보를 보이려면 수마다 분석이 필요하다. 그래서 `moves[i].analysis`를 더했다. 모델 수에만 값이 있고 사용자 수는 `null`이다. 기존 필드는 그대로다.
2. **포트 4321과 컨테이너 포트 공개** (작업지시자 지시): 개발 컨테이너 `chess-dev`에 포트 공개가 없어 Windows 브라우저에서 접속할 수 없었다. `docker/compose.yml`에 `127.0.0.1:4321:4321`(호스트의 localhost에만 공개)을 추가하고, 서버 기본 포트를 8000에서 4321로 바꿨다. 컨테이너 안에서는 `--host 0.0.0.0`으로 띄워야 한다.
3. **마지막에 고른 모델 기억**: 설정 창이 마지막에 고른 모델을 `localStorage`(`chess-app.model`)로 기억한다. 계획에 없던 작은 편의 기능이다.
4. **화면 캡처 미첨부**: 위 4절.
